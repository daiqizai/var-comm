# NeST-Com：两组分段熵编码与失配保护——有限验证方案 v1

**日期：2026-10-14。状态：实验设计，未实施、未运行。**

参考仓库：`daiqizai/var-comm`；核查快照：`078ff0d288491c09f658c1b1f43978e29d94a782`。
本文件提出一个新分支，不修改旧 raw 两组实验的 `NO_GO_STOP`，不覆盖旧注册、码流、策略或结果。先完成 LE0–LE1 并交付，再决定是否批准 LE2–LE3；LE4 和功率扩展均不自动启动。

## 0. 这次到底检验什么

**研究假设：分段条件熵编码能否降低基础信息的位数，让一个固定 1024 复符号的帧同时提供“差信道下有用的基础恢复”和“好信道下优于保守单码字的增强恢复”。**

不是再次证明“分层后比忽略误差的激进单码字稳定”。强对照必须是同样采用条件熵编码、同样知道 SNR 误差分布、同样经过校准的单码字。

旧 raw R1 的两组方案在匹配时与保守单码字恢复质量相同、失配时更低；DINO-J 平均差为 −0.009211，已停止。该结果说明原接口没有得到所需质量取舍，不证明新的分段熵码必然有效，也不证明所有分层保护都无效。[S1]

本轮改变两点：① 从 raw12 换成真正分段终止的 VAR 条件熵码；② 用较细的合法码长分配检查基础组与增强组的可靠性。**不同时加入组间功率、KEEP、反馈、重传、新网络或新的生成采样方法。**

第一阶段只研究发送端估计 10 dB、实际 7/10 dB；保持原假设误差分布：75% 匹配、25% 高估 3 dB。不是测得的估计器分布，也不是瑞利衰落。

## 2. 冻结场景、模型与数据角色

- RGB 输入保持原 256×256 像素。冻结视觉编码器、多尺度量化器、VAR、D_c、码本、null-class 1000、greedy补全、精度和数值选项；不新增训练。
- 总预算：1024 个复信道使用；头部68，正文956。第一版所有星座和已知填充的标称平均符号能量均为2，不做逐图QAM能量归一化。记录实际帧能量，不声称每帧严格等能量。
- 发送端仅使用估计 SNR=10、图像token和公共参数。实际信道是7或10 dB，发送端不得读取实际SNR、噪声、接收结果后再选配置。
- 接收端使用实际SNR进行解调。本轮隔离发送端配置失配，不讨论接收端估计误差。
- 主目标：每源先平均三次噪声，然后 `J = .75*DINO(true10) + .25*DINO(true7)`。
- PSNR和LPIPS监控代价，ConvNeXt留到冻结后验证；不使用本轮新增的DISTS/DreamSim改变选策。
- Pilot50：从旧R1固定calibration200的源ID集合中，按 `SHA256(canonical_json(["NESTCOM_LAYERED_EC_PILOT50_V1", source_id]))` 排序取前50，哈希相同按源ID字典序。不得看图或指标后替换。
- LE4使用原development100，且不进入新分支选策。这个集合已有历史研究使用，称后续冻结策略验证，不称新的盲测。common500不参与本轮搜索。
- 旧200的名单若无法准确恢复，报告BLOCKED，不临时抓50张图替代。

## 3. 源码格式：两个算术码流，保留跨尺度条件依赖

设完整尺度边长为 `[1,2,3,4,5,6,8,10,13,16]`，累计token数为 T_m。

基础组目标深度 `j_target ∈ {6,7}`。总目标 `(m,K)` 使用现有24个整尺度/四分位终点：`m=4..9, K ∈ {0,floor(L_next/4),floor(L_next/2),floor(3L_next/4)}`；总目标必须长于目标基础层。只把满足此条件的组合当作两组增强候选，退化输出另行记录。

### 3.1 基础组

编码第1到第j个完整尺度：

`C_B = arithmetic_encode(r_1,...,r_j ; VAR conditional CDFs)`。

从新算术区间开始，真实结束码流，得到实际长度 `b_B`。基础层完整尺度的恢复质量从同源无噪声诊断中读取，不假定第6或第7尺度一定足够。

### 3.2 增强组

从第j+1尺度到总终点 `(m,K)`：

`C_E = arithmetic_encode(r_(j+1),...,r_m,r_(m+1)[:K] ; p_VAR(. | decoded coarser tokens))`。

**重置的是算术编码区间，不是VAR条件。**增强段第一尺度仍以基础组token作为条件。发送端按真实粗尺度推进；接收端只按自己已经解出的完整粗尺度推进。

不能把已有整段码流做字节/bit切片，不能用 `length(full)-length(base)` 充当真实增强段长度。分段真实长度、两个终止开销和分段前后的差值必须单独记录。

当前 `PartialSourceCodec.encode_endpoints()` 已有非破坏式flush和部分尺度CDF截取，但没有“重置算术状态、保留VAR条件”的独立增强段接口，需要新增并验证。[S3]

### 3.3 接收端顺序

1. 从实际收到的68符号头部译出公共profile ID。
2. 按收到的profile译基础组，做CRC、长度、填充与规范终止检查；然后独立恢复基础token。
3. 基础组任一步不通过：输出固定RGB0.5；即使增强组物理CRC通过也不能把它当作独立可解的前缀。
4. 基础成功后，使用**实际解出的基础token**计算增强段CDF。增强组CRC/语法失败时保留基础token，丢弃整个增强段；不喂入乱码算术流，也不KEEP增强硬bit。
5. 两组均通过时使用完整实际收到前缀。按原VAR补全过程恢复缺失表示，再由同一个D_c解码。

CRC通过不等于真值保证。未检出错误按实际接收路径执行；token真值只用于输出固定后的审计。模型/文件/数值异常是工程失败，不能伪装成信道灰图。

规范性检查（由已解token重编码比较终止码流）可保留。发送端CDF和未传token不得进入接收API。

## 4. 资源计费、码长回退和空增强包

对每个非空组：

`n_g = q_g*N_g`, `k_g = floor(r_g*n_g)`, `C_g = k_g-13-16`。

正文格式：`13 bit实际长度 | 实际已终止算术流 | 已知零填充 | CRC16`。

所以两组显式信息字段共58 bit，而单组为29 bit；另有两次实际算术终止，其代价已经包含在 `b_B,b_E` 中。不得套用raw的 `12T+16` 或省略第二个长度字段。真实LDPC的BG、Z、filler、puncturing、interleaver、迭代参数全部由后端核对并登记。[S2,S5]

`N_B+N_E=956`，整个帧仍为 `68+N_B+N_E=1024`。

### 4.1 逐图回退规则必须预先定义

物理容量、目标j和目标终点在校准后固定。只允许根据发送端实际码长执行下面的确定性回退，不允许根据原图重建评分挑选。

- 基础优先：从 `j_target` 逐完整尺度降到4，选择第一个实际 `b_B <= C_B` 的基础层。不得为了多发增强层而故意跳过能装下的较长基础层。
- 固定实际基础层后，在总目标以下按**累计token数递减**检查登记终点，选择增强流实际 `b_E <= C_E` 的第一个终点。
- 所有正增强终点都装不下：选择显式“基础层only”profile。
- 基础层连m4都装不下：发送付费null-profile加已知填充，总长仍1024，重建固定灰图，记 `TX_SOURCE_UNENCODABLE` 并保留分母。

回退后的 `j_actual,m_actual,K_actual` 必须由付费profile ID明确告知接收端。目标值不能作为接收端免费的实际格式信息。

**空增强包规定：**第一版采用新语法：当收到的profile声明总终点等于基础终点时，增强组长度字段为0、其余已知零和CRC照常编码；接收端不进行增强算术解码。长度0只允许出现在该显式空增强profile，不能改写旧单码字 `len>=2` 的解析规则。记录这种帧占比，它不是获得额外两档质量的证据。

### 4.2 公共目录

先枚举离线候选，不要求全部候选都占头部ID。最终实际试验候选及所有合法回退终点统一登记在新目录，确保ID≤4095，编号不取模、不碰撞、不漏收费。所有方法都使用实际收到的ID和实际公有解析域；错但合法的ID照收，不靠知道发送方法纠错。

若最终目录超过4096，报告BLOCKED并单独设计头部扩展，不能静默删掉能改变结论的候选或免费传附加字段。

## 5. 对照：不能让两组独享熵编码或误差分布

| ID | 展示名称 | 定义 |
|---|---|---|
| S_nom | 单码字条件熵编码：名义配置 | 保留现有10 dB冻结熵码策略为锚点 |
| S_back3 | 单码字条件熵编码：保守退3 dB | 在同一源码/PHY候选族中，按真实7 dB质量校准后固定，不用raw 7 dB策略冒充 |
| S_robust | 单码字条件熵编码：鲁棒配置 | 按同一0.75/0.25目标、同一Pilot50选择；可退化为S_nom/S_back3 |
| E_two | 两组分段熵编码：等MCS参照 | 两组同q和同标称r，整数k/n差异保留；不声称同MCS等于同BLER |
| U_two | 两组分段熵编码：分级配置 | 基础/增强的N、q、r独立配置；第一版等标称功率 |

**U候选域必须显式包含E的合法点，不能强迫不等保护与等保护选出不同配置。**若最佳U就是E，说明没有建立“差异化保护”的额外作用，不能仅因类别名称而宣传UEP。

单码字与两组都有相同前缀终点集合、相同模型、相同长度回退权限（两组另有明确基础优先结构约束）、相同图像集合、相同误差分布和相同指标。不同码块布局的CRC/长度开销照实计入。

raw原R1仅用于旧失败解释；新主胜负不能只对raw。新方案不与P/Swin重训比较；若最终形成贡献，再决定如何接入已有外部主表。

## 7. LE1：50图源码可行性；默认第一批止于这里

### 7.1 三种实际源码长度

对同一源和同一最终终点分别计算：

1. 单段条件熵码 `b_single(m,K)`；
2. 基础段 `b_B(j)`；
3. 真正重启算术编码的增强段 `b_E(j→m,K)`。

记录 `b_B+b_E-b_single` 和两组相对单组额外29 bit字段开销。每个源可用一次逐尺度VAR概率推进，为多个独立算术状态生成这些流；独立RX验证不使用TX概率缓存。

为支持基础回退，基础状态覆盖j=4,5,6,7，不代表新增四个基础目标；实际目标仍只比较j_target=6,7。24个总终点中，基础j与比它更长终点共有68条边，50源最多3400个分段候选结束流。它们不是3400次图像模型推断；应复用同次TX条件概率遍历。

### 7.2 干净前缀质量

对24个终点的缺失项做50源恢复，最多 `50*24=1200` 个源/终点图像与DINO评分；同时直接计算PSNR。每张图所有状态共用同一原图。已有完全匹配结果复用。

报告基础层单独质量、完整终点质量、逐源差值和变差比例。不假设多收token在每个指标上都单调改善。原raw保守策略只作方向参照，不取代尚待选择的S_back3熵码。

### 7.3 源码资格检查

使用前6个固定Pilot来源，j=6/7、终点(m8,K0)/(m8,K42)，共最多24次独立基础+增强源码往返；生成完整的源码位流、独立重算CDF并核对token。另用合成/已有码流做CRC、越界长度、空增强、终止、基础失败后禁止增强解码等单元测试。

合成检查通过不等于真实模型往返通过；真实往返只证明已测数值配方。跨主机CDF不一致时先BLOCKED，不用TX的CDF修接收端。

### 7.4 第一批交付及决策

交付 `source_lengths.csv`、`clean_quality.csv`、`source_roundtrip_report.json`、原R1质量图、码长可行域和LE2所需测表缺口。说明是否存在候选能把两个非空组装入预算，以及基础恢复、额外恢复的实际幅度。

LE1没有信道成功概率，不允许给出“已超过鲁棒单码字”或“保证保底”的结论。完美接收状态仅是机制诊断，不是未加条件的性能上界。

上限：新TX概率遍历50次；缺失token时最多50次图像tokenizer；缺失干净状态最多1200个；独立分段往返24次；无线帧0；训练0。达到上限或缺关键资产则交付BLOCKED/当前结果，后续需要另行批准。

## 8. LE2：在有限PHY预算内找门限，不开全空间测表

### 8.1 候选网格

所有N均指复符号数。第一版 `q_B,q_E∈{2,4,6}`，不简单规定“QPSK才强保护”；可靠性由实际BLER判断。

`r_B,r_E∈{1/3,1/2,2/3,3/4,5/6}`。新增1/3也对单组开放，不强迫旧后端接受不支持的k/n。

粗N_B网格：256到768，每32符号；N_E=956−N_B。最多围绕4个有潜力的分配点，在±32范围按8符号细化。保留等保护信息比例分配所给出的合法N_B，即使它不在粗网格上。对每个固定(j_target,total_target)，由Pilot50的目标实码长取中位数，定义 `N_B_prop=round_even(956*(median(b_B)+29)/(median(b_B)+median(b_E)+58))`；仅使用校准图统计，得到的是每策略固定N_B，不是逐测试图调布局。对应有效后端布局应同时进入EEP与U域；无效点如实记录。

`k=floor(r*q*N)`，实际k/n与标称r同时记录，真实构造与往返检查后才能使用。禁止用float舍入造成多发送bit或免费filler。

### 8.2 两类筛选都要做

单组按完整实际码长与可靠性估计筛；两组按每源实际回退状态、基础/增强实际码长与可靠性筛。比较基线也可以使用该误差分布，不得只重新优化两组。

查表成功率记p_H、p_B、p_E。正确前缀近似模型为：

`Qtilde = (1-p_H)*Q0 + p_H*((1-p_B)*Q0 + p_B*(1-p_E)*QB + p_B*p_E*QF)`。

逐源计算后求平均，按真实SNR各自计算，再做.75/.25加权。头部错解、CRC未检出错误、真实载荷依赖与源码解析失败使该模型仅适合预筛，不是正式选模证据。源不适配/空增强是独立事件，不能挪到信道误块率中。

### 8.3 新测表预算与不确定性

优先复用同(k,n,q,解码器,映射,功率,噪声定义)的已有单元。新增最多96个packet/SNR单元，每单元128试验；至多24个影响候选排序的单元再从128补到512。总新增包试验≤`96*128+24*384=21,504`，包括需要补的头部单元，不另开无限上限。

有限128试验的零失败不写成真实错误率为零，输出二项比例区间。实际入围候选需要的单元若覆盖不足，则报告BLOCKED，不能强行指定表外成功率或把未测当作失败。未入围的大量配置只登记未测，不为了声称全局最优补全所有表。选择单元需同时覆盖最有希望的单组和两组，不按预期胜负分配。

基础组低端成功率、基础质量不足、增强长度/可靠性、头部失败、分段额外开销分别列出。若没有候选有正的预计J差，就交付筛选NO_PROMISING_CANDIDATE，不宣称证明所有两组无效；若不确定性足以改变排名且预算已尽，交付BLOCKED_TABLE_UNCERTAINTY。

## 9. LE3：最多3000帧真实小实验；只保留有限候选

在Pilot50、实际7/10 dB、3噪声下评价最多10个物理策略：3个U、3个鲁棒单组候选、2个EEP、原10 dB名义熵码锚点、7 dB保守单组熵码锚点；相同策略去重。锚点对应定义已在第5节给出，不使用raw代替。

`50*2*3*10=3000` 个正式物理图像帧；每帧至多头+两组，≤9000包译码。另有最多24个真实图像资格帧，独立记录，不暗中重复至通过。若有基础或增强错误，全部按第3节处理并计入分母。

噪声：新命名空间 `NESTCOM_LAYERED_EC_V1`，key为(namespace,stage,source_id,hat,noise_seed)，SHA256转大端整数种子后PCG64产生1024×2标准高斯；key不含方法、profile或真实SNR。cal seeds=4101/4102/4103。同源同seed用同标准噪声按真实SNR缩放，各方法波形仍各自真实生成。源ID只供外部仿真配对，不传给接收器或作为免费解码信息。公共counter=source_slot*3+noise_index。

评价DINO、PSNR、LPIPS。预筛时按低端7 dB预计质量选一个单组backoff候选作为必测锚点；真实LE3完成后，S_back3在所有已实测单组候选中按真实7 dB的校准DINO选定，S_robust按同一批候选的J选定。二者允许相同。原10 dB名义配置S_nom保持历史冻结状态。U从包含EEP点的两组候选选最高J。固定字典序打破完全并列，不让不同方法名称强迫不同配置。

### 9.1 预先固定的继续标准

同时满足：

- U − S_robust 的J ≥0.01；
- U − S_back3 的J ≥0.01；
- 匹配10 dB时，U的DINO高于S_robust，而不只是通过压低自身匹配质量使“下降幅度”变小。

以上是本轮控制投入的工程门槛，不是期刊录用标准。pilot属于选择数据，不对其结果包装成独立显著性。

同时报告但不替代主标准：匹配PSNR相对S_nom的损失是否≤0.3 dB；U从自身10到7的PSNR降幅是否≤3 dB；真实低SNR绝对质量；base-only比例、基础回退、空增强及失败率。

U若未超过EEP，不宣称不等保护的额外作用。若只超过原激进配置而没有超过强单组，交付NO_GO并停止。若有明显收益但未达当前门槛，交付原始数值，不改门槛，是否开展另一项任务由用户决定。

## 10. LE4：通过后才做100图冻结验证

单独批准后使用原development100，hat=10不变，实际7/10/13 dB，原开发seed2001/2002/2003但使用新命名空间。13 dB仅为额外压力点，不参与策略选择。

五方法：最终U、最终EEP、S_robust、S_back3、S_nom，去重但保留逻辑标签。至多 `100*3*3*5=4500`物理帧、13500包译码，四项指标全部评分；相同实际接收输入可以复用恢复但保留每个逻辑帧。

主对照固定为 U−S_robust、U−S_back3。每源先平均噪声，再形成每源J差，按源配对bootstrap 10,000次、seed2026101407；均值≥0.01且各主对照区间下界>0才称本轮冻结验证支持改善。区间逐点，报告所有不利结果。不要拼接两类边际区间。

冻结策略后可用p=0,.1,.25,.5,1画敏感性曲线，不再选策。报告实际接收三状态与同源基础/完整前缀质量，不只报告相对自身的退化dB。

### 10.1 生成协同的后续证据边界

首轮目标是超越强单组。只有这个目标达到，才值得追加同载荷单组与两组、各自VAR/Direct的2×2：必须固定实际源码终点并对新的单码字付费。不能直接把自适应回退后不同载荷的两套主方法叫纯接收器交互。

当前计划没有为同载荷2×2授权额外帧。它需要独立小任务；不能用帧条件均值或不同源的Q(m6)/Q(m7)代替交互证据。没有该实验也可报告两组系统收益，但不写“分层只有生成补全时才有意义”。

## 11. 组间功率只作为v2储备

本v1保持P_B=P_E=2。只有诊断表明确显示“源码装得下，但基础组保护占用过多符号”时，才考虑单独v2：

`N_B*P_B+N_E*P_E=2*956`，头部能量保持原来136。

可检验 `P_B/2 ∈ {1,1.25,1.5}`，由约束计算P_E，P_E≤0的方案不合法；进一步约束P_E≥1，避免完全饿死增强组。所有新等效SNR查表需单独声明缺口，不能免费外推，也不能两个组一起增加功率。

已有单组/两组等功率结果保持不变。功率v2与分段熵码效果分别归因。禁止在v1失败后偷偷打开功率、改p、改图集并仍使用同一注册称为通过。

## 14. 最终应该能回答的五个问题

1. 码流真正分段以后，额外29 bit字段和算术终止是否吞掉压缩收益？
2. 差信道下实际保住了哪一段前缀，其质量是否接近合理单码字？
3. 好信道是否真正多收了有用表示，还是多数帧又退成基础only？
4. 与鲁棒单码字/固定回退相比，平均质量是否更好？与等保护相比，差异化保护是否有额外作用？
5. 改进的成本是更多计算、不同源码粒度、不同保护，还是额外功率？本v1必须明确排除最后一项。

**本计划不把“分层+熵编码”预先定性为新颖性已解决。先验证一个具体且可能失败的机制；若成功，再以最近邻差异和真实收益评价论文贡献。**
