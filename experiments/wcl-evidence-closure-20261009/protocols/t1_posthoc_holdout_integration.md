# T1 post-hoc common500 supplement

The original common500 results have already been seen. These additional frozen entropy baselines are reported as a post-hoc same-source comparison. No old method, point, policy, interval, receive record, or output is replaced.

## Stage contracts

1. `t1_holdout_metadata.py freeze --calibration-completion <full/completion.json> --out <frozen_policy.json>` consumes the completed original calibration1000 ×3-noise DINOv2-L rankings. The two families may be in one completed stage or two separately supplied completions. It fixes six policies, one per family and4/10/19dB, with the registered lexical tie break. It refuses any calibration completion that used holdout.
2. `t1_holdout_metadata.py prepare` binds that freeze to the exact published common500 manifest SHA `b27128fb8eedee7f2cc74bed25c63e39e8add8c938c76d449f85c4b0d5a51e09`, original checkpoints, and original completed source statistics. This stage opens metadata only. Source identities/order must match exactly and remain disjoint from calibration1000.
3. `t1_holdout_source_owner.py --request <source-request.json> --environment-request <completed-T2-request.json> --out <fresh> --deadline-unix <deadline>` prepares source streams inside an explicitly owned GPU window. It reads original680-token caches; zero Encoder/VQ calls are needed. The original common500 checkpoints explicitly say arithmetic source coding was not generated, so the new VAR streams require actual work. One TX traversal per source flushes complete prefixes through the maximum selected target; actual lengths select a fallback separately for each frozen SNR. Only unique selected prefixes receive independent RX roundtrip work. Maximum500 VAR TX traversals and1500 independent VAR RX calls; actual counts and prefix levels are logged before/after each call. Static coding uses the exact train20k CDF and CPU integer codec.
4. The independent holdout PHY/render consumer binds the sealed source manifest. It uses `selected_by_snr[family][str(snr)]`, revalidates that selection against the freeze and actual TX lengths, and reads `streams[family][str(actual_m)]`. The latter contains only prefixes that have actual independent roundtrip cache evidence. Unselected TX attempts remain in `tx_prefixes`, with separate NPZ keys. A corrupted accepted profile/cache miss is decoded normally, never classified by TX truth. The consumer produces9000 entropy frames and at most18000 new packet decoder calls; its ledger is separate from original scientific ledgers.
5. `t1_raw_crc_drop.py --original-statistics-completion <r6/completion.json> --out <fresh>` reconstructs a diagnostic decision from original paid receive evidence and original per-frame metric records. Only actual body-CRC rejection changes output to constant0.5 RGB. All accepted outputs, including undetected errors, retain their original metrics/images. Original header failures retain their original output. The diagnostic performs zero PHY and zero VAR calls. A local read-only audit of the hash-verified original records found66 changed PARTIAL10dB frames in66 sources; WHOLE4/10/19dB and PARTIAL4/19dB had no changed frames. These are receive-state counts, not newly scored quality results.
6. `t1_holdout_metrics.py prepare` binds the completed entropy rendering, diagnostic mapping, original native-BPG four-metric runtime request/source, and completed adaptive-BPG metric cache/source. `run` uses the unchanged original SuiteBackend, FP32/B1 and original500-reference mismatch mapping. It restores only sealed matching source feature caches, and reuses quality scores only by exact source/reference/image/evaluator/mismatch identity. Original raw metrics remain exact copies except requested gray replacements. The new quality cap is9000 plus the number of required gray sources (currently66); identical entropy failure gray images and old cached gray scores reduce actual calls. No VAR rendering or packet decoding occurs in this stage.
7. `t1_holdout_statistics.py` consumes18000 metric rows:9000 new entropy frames plus9000 raw-DROP diagnostic frames. It produces48 summary rows and132 predeclared new paired rows, using the unchanged original500-source bootstrap implementation SHA `e401a77ac216368dc968ce023853ff7cdb2e0a2c94edbd3dd33407c0ba90054a`. Each source averages its three noises first;10,000 draws, seed2026100701, pointwise95% percentile intervals. The raw references'24 summary rows are copied, not recomputed. Identical source vectors reuse prior intervals, and exactly zero source differences have exact zero intervals without further resampling.

## Frozen comparisons and meaning

The entropy methods are compared with original raw complete-scale and partial-scale KEEP systems. VAR entropy is also compared with static entropy. Each raw CRC-DROP diagnostic is compared with its corresponding KEEP result, and the entropy systems are compared with both diagnostics. This is11 comparison prefixes ×3 SNR ×4 metrics =132 rows. Differences always mean method minus reference; LPIPS keeps its negative-is-better direction. Agreement is the ConvNeXt prediction agreement event, not classification accuracy. Percentage-point conversion belongs to presentation only.

The new entropy noise seeds are6201/6202/6203. Source pairing does not assert identical receive observations between different waveforms. No multiple-comparison adjustment or universal system winner is claimed.

## Render-to-metric interchange

The completed renderer exposes `status=T1_POSTHOC_COMMON500_RENDER_COMPLETE`, source_count500, frame_count9000, ordered source_ids, freeze descriptor, `source_request` descriptor pointing to stage2 metadata, original_statistics_completion descriptor, and outputs that seal `per_frame.csv` plus every referenced image archive. Each row includes family, point_id, snr_db, source_index, source_id, noise_seed, image_path, image_key, image_slot, image_sha256 and image_file_sha256. Image arrays remain lossless float32 CHW; both a single `image` array and an indexed `images` array are supported. The image hash uses the existing dtype/shape/bytes convention.
