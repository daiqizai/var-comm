# 0. 本轮必须回答的问题

**C：同样每图 N1024，不同图选择不同的源截断与传输配置，是否比所有图共用一个配置更有价值？**

**R：同样的总通信资源，在没有发送端瞬时 CSI 的块衰落下，少量反馈是否有效；根据前缀恢复质量设计决策，是否又优于简单 ARQ 和一次低比特 CSI 反馈？**

把三种证据分开：

1. 缓存质量与工作概率模型下的潜力；
2. 真实编码译码、缓存接收状态评分下的物理探针；
3. 新图像上的完整系统与独立指标验证。

本轮默认交付前两种。第三种只有单独明确决定后才进入视觉 GPU 队列。不得把查表预测称为真实图像链路结果，也不得把使用正确前缀缓存的评分称为已重新运行生成器。

# 4. 搜索使用的概率模型与验证方式

## 4.1 查表搜索是工作模型，不是连续曲线证明

可复用冻结 F1 点模型，明确标记其 dB 插值和尾部假设；报告各平均 SNR 下尾部概率质量。可以增加预先声明的替代拟合做敏感性分析，但不能选择最有利的拟合输出作为结果。

已存在的离散物理表，仅能复用于相同源载荷长度、编码、rate matching、调制、译码和功率配置。不能从一个码块长度直接套到另一个增量段。

模型用于生成短名单、检查潜力和设计策略。真实 Rayleigh 排名只根据后续独立信道随机数的 CPU 编码译码探针判断。若短名单仍依赖有问题的尾部，报告这个限制，不称完整候选集合的真实最优。

## 4.2 所有组先在同一个瞬时 SNR 下组合，再对衰落积分

令线性域平均 SNR 为 gamma_bar，瞬时 SNR 为 `gamma=gamma_bar*|h|²`。在无未检出错误的工作模型下：

`R_k(a) = integral p_H(gamma) * product_{g=1..k} p_g(gamma) * f(gamma) dgamma`

其中 `f(gamma)=exp(-gamma/gamma_bar)/gamma_bar`。

若头部/基础组失败输出灰图：

`F_i(a) = Q_i(gray) + sum_k [Q_i(k,a)-Q_i(k-1,a)] * R_k(a)`

不强制逐图 Q 单调，不把负的质量增量裁成零。概率积分的数值收敛与物理曲线模型的准确性分别报告。

## 4.3 未检出错误单列

上述简式不能覆盖 CRC 接受但内容错误的输出。查表阶段对这类事件保留独立概率项与质量范围；如使用一个点值近似，明确说明且做敏感性诊断。

CPU 真实探针用发送真值仅作评估端比对，不能把真值交给 RX 或决策器。凡出现错误接受、未知 profile 或其他无法映射到正确前缀缓存的输出，保留实际事件及其权重，不以干净前缀评分、不默默丢弃。

没有 GPU 时，这一小部分结果可给 DINO 的 [-1,1] 界或明确缺测；是否影响结论由实际频率决定。只对实际未建模事件加边界，不把所有未测连续 SNR 的概率都放任到任意值后再要求一个不可能收紧的包络。

# 5. 分支 C：逐图固定 N1024 的内容自适应选策

## 5.1 三种方法

### C-UNIFORM：所有图使用同一配置

对每个平均 SNR，在全部登记候选中选群体期望 DINO-L 最高的配置：

`a_uniform = argmax_a mean_i F_i(a)`

每图仍付费发送相应 profile，预算与 C-FULL / C-8 相同。另列仅单组候选的最优方案，但主参考使用允许范围内最强的统一配置，不故意限制它。

正式的 C-8 内部复核中，C-UNIFORM 也必须仅在同一 800 张构造图上选定，再用于 200 张复核图。全 1000 张上的群体最优可以另列为描述性参考，不能混作未使用复核图的基线。

### C-FULL：逐图全候选重建选择参考

对每张图，以源图和该图的前缀恢复质量选：

`a_i = argmax_a F_i(a)`

对比 `mean_i max_a F_i(a)` 与 `max_a mean_i F_i(a)`。

这是发送端高计算量参考；源图本来就在发送端，使用源图计算重建距离是允许的。它不使用真实类别，也不使用实际 h/噪声/接收输出。不得称它已经是低成本在线选择器。

在缓存里逐图取最优必然不差，这只是优化定义；差值大小和实现代价才是要研究的结果。

### C-8：最多八个配置的可实施候选字典

按 source ID 的固定哈希排序，把 calibration 划成 800 张字典构造图和 200 张内部复核图。该内部复核不是新的 holdout。

在 800 张图上：

1. 先放入 C-UNIFORM；
2. 每次加入使“每图选择字典内最优”平均收益增加最多的候选；
3. 最多八个不同配置，没有正增量则提前停止；
4. 相同收益采用固定的资源/ID 次序打破平局。

冻结每个平均 SNR 的字典，再在 200 张复核图上按该图自身的源质量选择。不得根据这 200 张的赢家另换字典或扩大到 16/32 个候选。

C-FULL 在复核图上仍可计算，作为高计算参考，但不反过来修改字典。

## 5.2 发送端与头部约束

- 每张图的总前向符号数不超过 1024；不得跨图平均、借用简单图预算或隐式增加重传。
- 选择的配置必须由实际头部发送给接收端。若使用 12-bit ID，验证实际可表达性、解析和完整码流；不能只在模拟器中传递 Python 配置对象。
- 接收端不能按 source ID、真实标签或图像难度直接获知发送配置。
- 相同 profile 的状态质量可以复用，不能把候选数乘成重复生成次数。
- 八个配置不一定只需八次 VAR：两组配置可能涉及两个终端前缀状态。报告每图所需的不同生成状态数、DINO 计算数和缓存命中率。

## 5.3 必交付结果

- 四个平均 SNR 的 C-UNIFORM / C-FULL / C-8 的平均质量、绝对增量和逐图分布。
- C-8 对 C-FULL 潜力的保留比例，分母接近零时标 N/A，不用巨大百分比包装小收益。
- 各 m/K/MCS 被选择的频率、质量增量的中位数和尾部，检查是否只改善少数图。
- 逐图质量中断率：先对每张图/接收状态判断，再按概率平均；不对群体状态均值做阈值判断。
- 可用的其他 calibration 指标原样交叉报告；不因结果更好而换主优化指标。
- 发送端完整枚举与八候选的预期推断成本清单；不将现有缓存下的 CPU 毫秒数当部署延迟。

## 5.4 阶段判断

以下是本轮预先建议的工程投入门槛，不是发表标准：

- C-FULL 在至少两个平均 SNR 上，内部复核图相对最强 C-UNIFORM 的模型均值增量达到 DINO-L +0.02，才优先为 C 分配真实译码探针。
- C-8 在相同至少两个点保留 C-FULL 增量的 70% 以上，作为“可压缩到小候选集”的初步线索。
- C-FULL 有潜力而 C-8 不足：交付 `POTENTIAL_HIGH_TX_COST`，不自动训练选择器。
- C-FULL 无明显潜力：交付 `NO_LARGE_GAIN_IN_WORKING_MODEL`，不扩跨图预算。
- 所有查表门槛均只触发 CPU 探针优先级，不能直接触发 GPU 最终实验或论文结论。

# 6. 分支 R：有限轮反馈与逐尺度传输

## 6.1 首轮只做普通 ARQ，不做软合并

- 最多 3 次前向发送，最多 2 次反馈。
- 第一段可传完整 m4、m5 或 m6；后续追加一到两个完整尺度，或者按冻结规则重发当前失败段。
- 若已经有兼容的终端部分尺度 Q，可允许最后一轮使用该部分状态；未缓存的状态不自动新增 GPU 生成。
- 正文使用实际 LDPC、CRC16、QPSK/16QAM；名义率候选复用现有 1/3、1/2、2/3、3/4、5/6，仅允许后端实际可编码的配置。
- 前向每轮独立解码，失败观测不软合并。更换保护时重新发送该段，不冒称增量冗余。
- HARQ、Chase combining、rateless 不属于本轮；这些机制需要累计观测/码布局建模，不能用单次 BLER 独立抽样冒充。

尺度按组递增，不要求每一个最粗尺度都单独付一个头部和一次反馈。任何反馈策略都允许提前停止；已用资源与未用预算分别报告，不转移给下一张图。

## 6.2 必须先算控制开销

采用一个便于复用且不隐藏成本的首版协议：每次前向发送使用独立的 68 符号头部，携带登记的动作/节点 ID；序号、段范围和解码配置由公开码本唯一确定。每段正文另付 CRC16 和实际 LDPC 编码长度。

反馈主场景先假设可靠反馈，代价 `c_fb=32` 个等效复符号；敏感性取 16、64。`c_fb=0` 仅作理想诊断，不进入主要成功判定。16/32/64 是工程代价扫描，不是 1-bit ACK 的实际标准空口长度。

最大资源约束：

`sum_t (68 + body_symbols_t) + n_feedback*c_fb <= 1024`

两次反馈、三次前向、c_fb=32 的路径，头部与反馈最多占 `3*68+2*32=268` 个符号，正文至多 756。单次无反馈方案有 956 正文符号。不得为了让新方案好看而强迫单次基线承担不需要的额外头部。

前两轮若请求后续决策，均计一次反馈；第三轮后停止，不要求额外最终 ACK。路径截断前检查最坏剩余资源，每一条 ACK/NACK 路径都必须满足上限。

等待、收发转换和传播时间另列：报告前向轮数、反馈轮数以及 `T = T_waveform + n_turn*T_turn`。没有真实场景的 T_turn 时给公式/代价敏感性，不声称已经达到某种实时性。

## 6.3 四个必要方法

### R-FIXED：最强无反馈固定方案

每个平均 SNR 选择最好的固定单组，以及最好的固定两组；两者中的较好者作为强无反馈参考。它只知道分布，但允许充分优化源截断、MCS 和分组。

### R-ARQ：简单尺度 ARQ

预先选择有限的阶段边界和 MCS。规则固定：ACK 则按计划前进，NACK 则重发同一段同一配置；预算不足则停止。固定阶段/MCS 也在相同 planning 资产上优化，不故意选择一个差的初始 m。

### R-AWARE：前缀质量感知的有限反馈决策

状态包含：已接受前缀、剩余预算、当前轮数和可观察 ACK/NACK 历史。动作可为：停止、追加登记尺度段、重发失败段、以更强的合法配置重发失败段。

首轮使用 calibration 群体平均 Q；不加入 C 分支的逐图选择。

用有限深度决策树枚举或动态规划求解：

`V(H,b,t) = max_action E[terminal_Q | observable_history=H, remaining_budget=b, round=t]`

发送端不直接读取模拟器里的 h。若用概率模型推断 h，其后验仅由先验和 ACK/NACK 更新。

例如无合并工作模型中，给定同一个 gamma，多次 NACK 的似然是相关动作失败概率的乘积；不能每次失败后重新使用未条件化的平均成功概率。接收端 ACK 由实际协议的 CRC 接受决定，不由发送真值决定。

### R-QCSI：一次 2-bit 量化 CSI + 自适应单次发送

在共享的完美 RX-CSI 假设下，接收端先反馈四档信道之一，发送端按该档选择一次传输配置。阈值和对应配置只在 planning 的物理表、calibration Q 上优化。

候选分界点预先固定为 `{-5,0,4,7,10,13,19} dB` 中任取三个，产生四个区间；最终只选一组三个阈值，不在 verification 后重新改。

同样按 c_fb=16/32/64 计一次反馈，单次前向头部仍付 68；正文预算为 `1024-c_fb-68`，必须重新核对实际编码长度，不能借用完整 956 正文长度的性能。

2-bit CSI 不是免费 bit，也不能因 ACK 只含 1 bit 就忽略空口控制和等待。在本轮可靠反馈探针下，两者使用同一代价假设；未来有噪反馈要对双方采用一致的可靠性要求。

R-QCSI 是反馈方法的关键对照：如果它已经取得相同或更好的质量且往返更少，不得把逐尺度 ACK 方案描述成更有价值的反馈机制。

## 6.4 反馈过程的真实状态

- 单张图的 h 在所有轮次固定；重传不产生新的独立衰落。
- 每轮噪声独立，失败重传不软合并。
- 头部失败或正文 CRC 拒收按公开规则产生 NACK；接收端保留此前已接受前缀。
- CRC 错误接受可产生错误 ACK。发送端按实际 ACK 行动，评估器只在事后标记错误。
- Header profile ID 也必须实际编码、解码和解析；不得免费告诉 RX 本轮采用哪个节点。
- 同一树节点必须由公开状态和收到的头部确定；节点/动作数不能超过头部表达能力。

## 6.5 新增物理表的处理

递增段通常不同于整条前缀，它的 payload 长度与实际码块未必已经在旧表中。先生成 `R_MISSING_PHY_CONFIGS.csv`，仅为资源可行且可能入围的动作补表。

不得在不同码块长度、不同有效码率之间假装有精确通用 BLER 曲线。若缺项过多，则缩小预先说明的动作集合并记录覆盖，不声称获得一般多轮最优。

先保持普通 ARQ，以便复用兼容的单次概率表；真实探针仍使用实际 LDPC 解码，而不是只抽 Bernoulli。

## 6.6 “追回 CSI 差距”仅作辅助图

可以报告相对重新计算的 CSI 参考追回多少，但参考必须标明候选、预算和反馈代价。旧的一次发送 CSI-REF 不自动上界新增多轮策略。

若参考差距接近零，比例标 N/A；比例超过 1 不裁掉，而要检查是否比较了不同协议族。不能仅凭“追回一半”进入下一阶段。

主判断是 R-AWARE 相对 R-FIXED、R-ARQ 和 R-QCSI 的绝对质量/开销差别。

## 6.7 阶段判断

在主反馈代价 c_fb=32 下：

- R-AWARE 相对最强 R-FIXED 的模型 DINO-L 增量在至少两个平均 SNR 达到 +0.02，才优先进入真实 CPU 验证。
- 模型优势只在 c_fb=0 出现：交付 `FREE_FEEDBACK_ONLY`，不推荐完整图像实验。
- 相对无反馈有收益、但不优于简单 ARQ 或 R-QCSI：交付 `FEEDBACK_VALUE_ONLY`，不得称前缀质量决策已有独立方法增量。
- 真实 CPU 验证后，只有资源已计费的 R-AWARE 在至少两个平均 SNR 上，相对最强已验证简单参考仍达到 +0.02 且配对区间支持正向，才给出 `METHOD_GAIN_CANDIDATE`。
- 该标准是决定是否值得投入完整图像验证的工程规则，不是论文录用门槛。不通过不追加样本追求通过，也不外推为所有反馈策略无效。

# 7. V：共享的 CPU 真实衰落译码探针

## 7.1 为什么增加这一小步

本轮不再要求一个对所有未测连续 SNR 任意行为都有效的包络。对少量冻结策略直接抽取 h 和噪声，使用真实编码译码评估平均表现。

接收结果为已缓存的正确前缀时，读取相应逐图 Q，不运行 VAR。因此它是“实际信道 + 实际译码 + 缓存状态评分”的物理探针，不是只查 BLER，也不是重新执行完整视觉链路。

## 7.2 固定样本与随机数

- 从 calibration 的 200 张内部复核图中，按固定 source-ID 哈希次序取 64 张，不能按图像内容或已有收益挑选。
- 每源、每平均 SNR 固定 16 组独立 h/噪声，即每方法每工作点 1024 条轨迹。
- 各方法共享源图和 h。实际噪声按预先生成的时隙/轮次计数器切片，策略不能读取尚未发生的噪声。
- 若需要 planning 的物理试跑，使用完全不同的随机数命名空间；verification 输出不能回流选择策略。
- 新种子建议使用 `2026100501`（数据排序）、`2026100502`（planning）、`2026100503`（verification）、`2026100504`（bootstrap）；与旧目录隔离。

这仍是 calibration 内部的工程复核，不是独立 holdout。结果用于确定是否值得做正式图像实验。

## 7.3 短名单和基线

每个平均 SNR 最多验证六个不同真实策略，优先保证：最强固定参考、C-8（若入围）、简单 ARQ、R-AWARE、R-QCSI。必要时第六项用于一个可能改变强基线排名的近邻。

校准模型下最优不等于真实最优。若两个固定基线接近，应把它们都保留，不只验证新方法而省略竞争基线。

R-QCSI 和三轮协议产生的新码块都要计入物理预算。不能为适应预算临时降低某条强基线的载荷或保护候选范围。

## 7.4 输出与不确定性

报告均值、逐源三类失败、接收状态频率、平均与最坏资源、反馈轮数、DINO-L 变化以及模型预测残差。

按 source 先平均 16 次物理随机实现，再做配对 source bootstrap，建议固定 5000 次；另报 Monte Carlo 标准误。该区间是小型复核集上的描述性结果，不覆盖所有模型选择和训练不确定性。

存在未检出错误时，报告其实际频率及未评分贡献范围；如果足以改变结论，则交付 `NEEDS_CORRUPTED_STATE_RENDER`，不偷偷把它变为正确前缀。后续如要渲染这些状态，进入单独 GPU 任务。

真实结果不满足门槛就报告；不为收窄区间临时增加源图或随机重复数。

# 8. 资源与停止边界

## 8.1 两个分支共享，而不是各拿一份资源上限

- 新 C/R/V 全部共享最多 2 个 CPU worker，每 worker 最多 2 线程；低优先级。
- 禁止新分支使用视觉 GPU；相关进程 `CUDA_VISIBLE_DEVICES` 为空。
- CPU 核心按运行环境的可用集合选取，不照抄旧机器的核编号。尽量避开 A1/A2 的数据准备资源。
- 新增实际编码译码总上限为 250,000 次码块解码，头部与正文均计；每个发生的重传再次计费。
- 新增需要单独标定的物理配置上限为 48 个。上限是本轮工程规模，不是理论足够性保证。
- planning/补表最多分配 50,000 次，verification 预留最多 200,000 次；不能把 verification 预算提前用于反复挑策略。
- 先运行少量 CPU 工程测试确认接口和资源。不用 CPU 速度推断 GPU 生成成本，不承诺某日自动完成。

如果上限不足以完成冻结短名单，先完整交付已完成阶段及缺项，不压缩出一个不匹配的基线，也不降低验证条件。

## 8.2 允许完成，不要求每条线都赢

可能的交付状态：

| 状态 | 含义 |
|---|---|
| `MODEL_POTENTIAL_ONLY` | 查表存在空间，尚未经过实际译码 |
| `POTENTIAL_HIGH_TX_COST` | 全候选逐图选策有空间，小字典无法充分保留 |
| `NO_LARGE_GAIN_IN_WORKING_MODEL` | 本轮工作模型和候选集下没有足够的初步增量 |
| `FEEDBACK_VALUE_ONLY` | 反馈有价值，但新策略不优于简单反馈参考 |
| `FREE_FEEDBACK_ONLY` | 只在零反馈成本假设下有优势 |
| `METHOD_GAIN_CANDIDATE` | CPU 物理探针达到投入下一阶段的规则 |
| `UNCERTAIN` | 有限资源或模型/缺失评分影响排序，不能定论 |
| `MISSING_ASSET` / `INCOMPATIBLE` | 缓存或协议不支持对应分支 |

旧 F1 的停止状态不被这些新状态覆盖。没有任何状态自动宣布可发表、全面优于 P，或自动启动更多带宽。

# 9. 暂不启动的任务

本轮不启动：

- HARQ 软合并、增量冗余、rateless；
- 跨图片借预算、批量资源池、在线视频调度；
- soft embedding 接收旋钮或来源条件化 Dc 的训练；
- 新的算术编码流水线；
- C 与 R 的联合内容-反馈策略；
- N512/N2048 新分支、旧 UEP N2048 扩展、广播；
- development 上的调参、holdout 或自动重训练。

上述项目不是永久停止，只是不属于本轮有界验证。来源条件解码器与无类别算术编码若后续独立启动，应分别登记，不能拿其收益补偿本轮反馈或内容方法的失败。

# 12. 可直接发送给 Codex 的任务摘要

在 VAR_COMM 中按本文件创建独立的 content-feedback 探针，不中断 A1，不改变 A2 队列。先核对实际运行状态及输入绑定，保留旧 F1 UNCERTAIN 与旧 UEP 停止结论。

第一条分支 C：只使用 calibration 的逐图正确前缀质量与兼容物理表，固定每图 N1024、无发送端瞬时 CSI，比较群体统一配置、逐图全候选参考和八候选字典。字典在固定 800 张图上构造、200 张图上内部复核，不能借用 development 或真实接收噪声。配置 ID 付费发送，不做跨图预算分配。

第二条分支 R：固定每图同一个 Rayleigh h，最多三次前向、两次反馈，先做不合并 ARQ。每轮前向头部、正文 CRC/LDPC 与反馈都计入 1024 共享时隙资源。主反馈成本 32，敏感性 16/64，零成本只作诊断。比较最强无反馈固定方案、简单尺度 ARQ、前缀质量感知决策，以及一次 2-bit CSI 反馈。策略只看实际可观察历史，不读取真实 h；R 首轮不混入内容自适应。

查表只作搜索。达到登记的初步潜力后，在新命名空间用少量冻结策略做真实 CPU 编码译码、随机 h/噪声以及缓存状态评分；不要求不可实现的任意连续曲线包络。错误接受状态单列，不假装正确。新任务共享最多两个 CPU worker、每个两线程、零视觉 GPU；新增解码总上限 250000 次，补表/规划最多 50000 次、验证预留 200000 次，不超预算自动扩展。

所有正、负和不确定结果完整交付。不要启动 HARQ、跨图资源池、来源条件解码器训练、算术编码或新带宽。完成本轮后停止，只给出是否值得开展下一项正式图像验证的建议。
