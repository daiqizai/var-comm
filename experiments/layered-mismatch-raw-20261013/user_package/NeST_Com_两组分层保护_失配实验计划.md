## 0. 本轮要回答的问题

在**同一逐图符号预算、同一发送端 SNR 不确定性、相同视觉模型**下，两组尺度保护能否比：

1. 按估计 SNR 选取的现有单码字；
2. 固定退 3 dB 的单码字；
3. **同样针对误差分布重新优化的单码字**；
4. 两组近似等码率保护；

获得更好的平均恢复质量？接收端 VAR 是否增加了“只收到基础组”这一状态的价值？

预先分开三个结论：
- 系统价值：两组方案是否超过强单码字和保守回退。
- 保护机制：优势是否来自不等保护，而不只是分成两个可独立校验的码块。
- 先验交互：在固定发送内容和物理结果后，VAR 是否改变分组相对单码字的收益。

不预设“分层保护只有 VAR 才有意义”“一定平滑退化”“这是唯一的创新方向”。经典渐进通信也能从分层保护获益。raw 分支成功也不能直接当成熵编码主方案的成功。

## 1. 已有证据与执行优先级

### 1.1 旧 UEP 结果不能怎样使用

`reports/uep_prior_aware_20261004.md` 和 `results/prior_aware_uep_20261004/extension_gate.json` 表明：
- 4/7/10 dB 的最终 B3 **退化为单组**，因此与单组零差值不是“真正两组只损失零”的证据。
- 13 dB 使用两组，PSNR 差为约 -0.0621 dB。
- 原期望质量模型没有通过全部已登记验证条件；它可以用于筛选，不直接代替真实链路选策和结论。
- 旧 B4 按 direct-Q 选配置，但最后仍用 VAR 重建；不能把它当作本轮真正的有/无 VAR 2×2。
- 旧链路支持 QPSK/16QAM，partial 部分含旧排序条件；本轮需要当前 raw 的光栅接口和 64QAM，不能直接整体复制旧协议。

另外盘点历史未知瞬时 CSI / Rayleigh / 反馈查表分支。本轮新增点是**固定估计 SNR 条件下的误差分布、实际两码块接收、强鲁棒单组及真实 2×2**，不是再次运行旧匹配 SNR 搜索。

### 1.2 最新主线已经推进

在本快照：

- 原先独占服务器要求已被用户改为记录负载的共享 H800 测量。新分支不得自行恢复旧独占门槛，也不能与本人的正式计时占用同一 GPU、污染其测量。

## 2. 固定场景：先测估计错误，不混入衰落

### 2.1 主网格

- 图像：原 256×256 RGB 预处理。
- 预算：每图 N=1024 个复符号。
- 信道：AWGN；一个帧的两组使用**相同真实 SNR**。
- 发送端只得到 `snr_hat`；接收端解调及其网络条件使用 `snr_true`。
- 这里隔离“发送端选错配置”，不是收发两端估计误差的联合实验。
- 定义 e = snr_hat - snr_true。e=+3 为高估，e=-3 为低估。

| snr_hat (dB) | e=+3：高估 | e=0：匹配 | e=-3：低估 |
|---:|---:|---:|---:|
| 7 | true=4 | true=7 | true=10 |
| 10 | true=7 | true=10 | true=13 |

共 6 个条件。**同一行的发送配置固定**，不随真实 SNR 改变。选择这一网格是为了覆盖双向误差并避免“hat=1 时回退到 -2 dB”的未校准外推；没有按最终胜负挑点。

不机械沿用 true=4/7/10 × hat=true±3 的九点表来计算鲁棒选策，因为每个 hat 对应的误差支持不完整。旧网格中完全匹配的单个记录可以核对后复用，但不能将不同 hat 的观测拼成同一发送策略。

### 2.2 预设误差模型与敏感性

主要问题是“通常匹配、偶尔高估”。本轮**人为规定的设计场景**为：

- P(e=0 | hat)=0.75；
- P(e=+3 | hat)=0.25。

这不是实测估计器误差分布。每个候选在每个 hat 的目标：

`J(a|hat) = 0.75 * mean_DINO(a, true=hat) + 0.25 * mean_DINO(a, true=hat-3)`。

同时报告 e=-3 压力点，但不把它事后加入选策目标。冻结策略后只通过重加权报告 p∈{0,0.1,0.25,0.5,1} 的高估比例敏感性；**不为每个 p 重新选赢家**。若未来要声称对一般双向误差鲁棒，需要另行设计其分布与验证，不由本次一侧风险模型推出。

## 3. 主协议：raw，两组，失败组丢弃

### 3.1 内容与资源

令 T_j 为前 j 个完整尺度的 token 数，T(m,K)=T_m+K。

- 基础组 G1：完整尺度 1..j；
- 增强组 G2：尺度 j+1..m，加边界尺度 m+1 的光栅前 K 个 token；
- j 是完整尺度边界，j≤m，且 T(m,K)>T_j；
- 两组分别 CRC16、LDPC、速率匹配和 QAM。

`k1 = 12*T_j + 16`；`k2 = 12*(T(m,K)-T_j) + 16`。

对实际编码长度 n1,n2 和每复符号位数 q1,q2：

`68 + n1/q1 + n2/q2 + N_idle = 1024`。

必须使用后端验证后的整数布局；登记实际 k/n、base graph、lifting、译码算法、迭代次数、LDPC filler 和速率匹配。头部仍采用 68 次 QPSK，公共 ID 唯一确定 j,m,K、两组长度与 MCS；不可给 RX 免费传入真实配置。固定公共配置表超过 12-bit ID 范围时，先冻结本轮实际候选/最终配置子表，不截断 ID 或复用冲突 ID。

同标称星座平均 E_s=2，保留逐帧实际能量；剩余符号使用原已知带能量填充。不得在基础组额外增加功率而不计入总资源。

### 3.2 第一个有限候选集合

- 来源终点：m∈{6,7,8}，K∈{0, floor(L_next/4), floor(L_next/2), floor(3L_next/4)}。
- 额外保留当前单组在 hat 及 hat-3 选中的终点作为候选；不把已知单组赢家排除。
- 分界：j∈{5,6,7}，按 j≤m 与 G2非空过滤。
- 基础组符号数：N1∈{256,384,512,640,768}；N2=956-N1。
- q1,q2∈{2,4,6}，先限制 q1≤q2；这是一种有限的“粗组不使用更高调制阶数”设计范围，不代表所有 UEP 的最优解。
- r_g = k_g/(q_g*N_g)，只保留 r_g≤5/6 且当前真实 LDPC 后端支持的布局。下界和母码/filler限制使用后端，不伪造可用码率。
- 不等保护不能只由 r1<r2 或 q1<q2认定：最终必须报告两组实际拒收率、检测后错误和接收状态。
- EEP 候选：相同 q1=q2=q，按信息位比例分配 956 个正文符号，N1=round(956*k1/(k1+k2))，N2=956-N1；报告舍入后的实际码率。因块长不同，不宣称两组 BLER 恰好相同。

这组候选控制搜索量。允许分组内使用已登记的高阶调制，不让新分支赢过被去掉64QAM的单组对照。旧 actual_phy.py 的 `q=2 if QPSK else 4` 必须显式改为 q∈{2,4,6} 的新适配入口；不能让64QAM落入旧的else分支。

### 3.3 接收规则先只设一种

| 收到的合法头与组 CRC | 用于主方法的实际 token |
|---|---|
| 头失败 | 固定 RGB=0.5 输出 |
| G1失败（不管G2怎样） | 固定 RGB=0.5 输出 |
| G1成功、G2失败 | 仅使用实际收到的 G1 token，恢复前 j 尺度 |
| G1、G2均成功 | 使用实际收到的完整选定前缀 |

“成功”指实际 CRC/字段校验通过，不是仿真端知道的token全对；未检出错误必须真实重建。G1失败但G2成功仍不可越过缺失的粗前缀。保留状态计数，包括误接受。

**不在第一轮加入“失败组也KEEP”。**否则既改变分组，又改变坏token使用方式，且不再能解释为纯粹短前缀恢复。现有单组主基线保留自己的KEEP规则。单组鲁棒候选允许在校准中选择KEEP或DROP，两种都报告，防止靠削弱单组失败处理得到收益。

若以后研究两组KEEP，单独定义：只KEEP哪个失败组、何时停止、哪些后续组忽略；同一物理输出上复用诊断。不得把KEEP后的含错前缀称为正确短前缀。

## 4. 五个必要系统对照，外加一个机制用匹配对照

| 内部名 | 对外名称 | 规则 |
|---|---|---|
| S_nom | 单码字：按估计SNR配置 | 当前raw433已冻结策略 a_nom(hat)，原KEEP |
| S_back3 | 单码字：固定3 dB回退 | a_nom(hat-3)，原KEEP；每帧都回退，不读真实SNR |
| S_robust | 单码字：误差分布感知配置 | 当前raw433可行集合，在相同J目标下重新校准；原赢家与backoff必须保留；KEEP/DROP按校准选择 |
| E_two | 两组：近似等码率保护 | 按相同J目标与来源终点搜索有限EEP集合，DROP |
| U_two | 两组：分级保护 | 本轮两组集合按相同J目标选择，DROP |
| S_payload | 单码字：与U_two同源载荷 | 固定与U_two相同m,K和token顺序，仅合并成一个CRC16/LDPC块；用于2×2，不代替S_robust |

S_payload 默认采用 U_two 的增强组调制阶数和满正文预算；由于 q1≤q2，其总信息位通常可装入。必须经过后端合法性检查。无法满预算时按预先规定的后端有效最大码长加填充；不得根据测试分数挑选此对照。S_payload 使用DROP，与U_two相同失败分组解释。

S_robust 必須有与 U_two 相同的误差分布信息、候选筛选与校准机会。只赢原来按匹配SNR优化的S_nom或固定backoff，不足以将收益归为分层机制。

## 5. 校准：先筛候选，再少量真实链路

### R0：只读复用与候选注册

- 核对模型、tokenizer、Dc、null类别、raw光栅顺序、码本、噪声和指标身份。
- 读取旧UEP的BLER、clean-prefix Q、失配结果和未知CSI分支，输出“可复用/缺失/不兼容”清单。
- clean Q 表中 m,K相同但排序不同的数据不能混用；完整粗前缀可以单独核对。
- 枚举真实后端支持的有限 S/U/EEP 配置，输出唯一物理key与表外BLER缺口。
- 表外成功率不给阶跃硬猜，不把未测当零/一；只为影响入围的少数候选补表。
- 对每个hat提名：U最多3个，S最多3个，EEP最多2个，另保留S_nom、S_back3，最多10个不同物理配置。
- 旧模型验证未全通过，表格模型只作筛选。不能用它宣布GO、把KEEP失败质量全当灰图，或自称找到了全部动作的全局最优。

可用筛选近似：P0（头/G1失败）、P1（仅G1）、P2（两组）。在CRC通过近似正确的理想化下，E[Q]≈P0Qgray+P1Qbase+P2Qfull。真实链路须验证状态频率及含错通过事件；不将源群体相关性、相同SNR条件与无条件独立混为一谈。

### R1：200张原校准图上的有限真实选策

- 从原1000校准清单按SHA排序固定200张，种子/字符串域 `UEP_MISMATCH_CAL200_V1`；不从development、common500或new100选图。
- 配置候选和选择规则写入新registration。其余800张不用于这轮追加搜索。
- 主网格6条件，每源3噪声，每hat最多10个不同物理候选。
- 物理帧上限：`200*2*3*3*10 = 36,000`。
- 单组KEEP/DROP共用同一实际解码，额外最多3个接收版本/hat；VAR逻辑重建输出上限46,800。依据相同实际接收输入复用重建，不减少逻辑分母。此处是保守上限，不代表一定要跑满。
- 主目标只用DINOv2-L；PSNR/LPIPS作为代价监测。ConvNeXt不参与筛选、选策略或GO判断。
- 每个hat在U/S/EEP各自冻结一个J赢家。若S_robust选中backoff或原单组，保留这种退化，不强迫新名称选出不同配置。
- 数据库复用粒度是来源、像素、协议、发送配置、实际接收字段、噪声及模型身份；不能只按相同token数复用。

新噪声建议：完整1024×2标准高斯数组由来源ID、hat、noise_seed和新namespace共同决定，三seed固定为4101/4102/4103。对同来源/hat/seed，在不同true SNR下只改变噪声尺度；各方法可使用同一标准数组，但实际接收波形当然不同。旧记录的namespace不匹配时不能冒充这一配对，只可另列历史锚点。

### R1之后的工程门槛

先按两种hat等权的J比较：
- U_two相对S_robust与S_back3的**平均DINO增量均≥0.01**，并且两个hat各自的增量均为正：进入有限R2验证。
- 只超过S_nom，或不能超过强单组/回退：交付并停止该设计；不调高“高估发生率”寻找有利混合权重。
- 只在一个hat改善：记录ONE_POINT_PROMISING，不自动增加其他SNR追求显著。

这0.01是本轮投入门槛，不是WCL发表门槛。可以在正式启动前由用户改一次；实际结果出现后不改。

“匹配PSNR损失≤0.3 dB、同策略高估损失≤3 dB”单列为强鲁棒性目标。若J改善但没有达到它们，结论是TRADEOFF_ONLY，而非已经实现低代价平滑退化。

## 7. 真正的2×2：同载荷、同观测、只切换恢复器

| 发送架构 | Direct Dc | VAR补全 + Dc |
|---|---|---|
| 与U相同token载荷的S_payload | S,D | S,V |
| 两组U_two | U,D | U,V |

固定U的j,m,K、两组MCS，以及S_payload的m,K/MCS；四个格子都不重新选策略。每种架构内部的两个接收器必须使用**同一实际接收事件、同一接受token、同一拒收规则**。Direct仅把缺失残差置零；对部分边界尺度，已收到位置仍累加，缺失位置为零，使用同一Dc。

对越大越好的Q定义：

`I = (Q_U,V - Q_S,V) - (Q_U,D - Q_S,D)`。

LPIPS先以Q=-LPIPS代入，原始LPIPS差值表仍保持原符号。以同一来源上的上述四项合成I后bootstrap，不能用两个独立置信区间相减。

- I>0且区间支持：在这些固定载荷/配置下，生成补全增强了分组的相对收益。
- I≈0但U优于S：分组可以有效，但没有建立“特别依赖生成先验”的交互。
- Direct下也有UEP收益：正常结果，不是失败。不能要求其无效来证明自己的方案。
- 该2×2没有重新优化Direct配置，所以不能由它宣称VAR改变了全局最优保护方案；要说最优配置改变需另做对称选策实验。

另报告“仅基础组”与“全部组”两种状态的Q、状态概率及分母。比较固定来源的base/full前缀截断损失，不能直接拿来自不同方案/工作点的13.8%、46.8%、71.2%、81.6%相减充当真实分组交互。

## 8. 指标、统计与判定层次

### 8.1 主指标

每源先在各(hat,e)内平均3噪声，再按固定0.75/0.25合成J，最后对hat7/10等权平均。用这一源级J差值做主比较，报告均值及95%来源配对区间（10,000次，固定新seed2026101307）；相同重采样索引用于所有方法/交互。各hat及压力点单独给出，不用总平均藏掉某个工作点。

R2总体支持“有价值”的要求：
- U−S_robust与U−S_back3的主DINO差值均≥0.01且对应区间下界>0；两个hat点估计均为正。
- ConvNeXt作为独立选策外评价报告，若有明确不利方向必须保留，不能自动改主指标。
- 与EEP的比较决定是否能把优势专门归因于**不等**保护。若两组EEP同样好，则优先用更简单的方案，不能继续宣传不等保护不可或缺。

所有区间是预设对比的逐点区间，不宣称已经对全部多重比较作联合校正。样本量固定，不为得到显著性重复加样本。

### 8.2 鲁棒性目标单列

- 匹配代价：PSNR_U(hat,true=hat) − PSNR_S_nom(hat,true=hat)。目标≥−0.3 dB；同时报告DINO与一致率。
- 自身高估损失：PSNR_U(hat,true=hat) − PSNR_U(hat,true=hat−3)。目标≤3 dB。
- 同一坏信道下的绝对质量：U与backoff/S_robust同时比较，不允许一个本来就很差的匹配输出因为“下降小”而被称为鲁棒。
- 灰图率、基础组拒收率、仅基础组比例、全组比例、CRC未检出错误和具体接受前缀分布。
- 可选但预先固定的低质量帧事件：DINO<0.5。先逐帧算指示量，再按来源统计/重采样；不是先比较各状态平均DINO是否低于阈值。它叫“表征低质量帧率”，不是完整语义正确率。

只有“主要质量取舍有利 + 匹配代价目标 + 失配目标”都得到支持，才能使用“本次误差范围内低代价分级退化”之类较强表述。两组仍保留基础组与头部失败导致的断崖，不等于消除了数字悬崖。

## 9. 输出三张图和一张小表

1. **真实SNR—质量曲线**：分hat7/10两个面板；每条线在面板内保持同一发送配置。五系统方法齐全，四指标分别导出。
2. **全组/仅基础组/无有效基础组三状态比例 + 对应质量**：确认改善确实来自基础信息保留，而不是隐含修改了输出规则。
3. **2×2交互及高估概率敏感性**：主交互I与来源区间；p=0..1的冻结策略重加权曲线，不重新优化。
4. **最终参数表**：j,m,K、q1/q2、实际k/n、正文/头部/填充符号、原/坏信道基础组拒收率、匹配代价。

完整CSV必须保留各source、hat、true、noise、发射配置ID、真实收到ID、两个CRC、保留token数、输出模式、全部四指标、实际能量和复用身份。

## 10. 与熵编码主方案衔接

raw两组成功后，不直接将其叠加到熵编码500图结果。若论文最终主方案仍为条件熵编码，则需要单独验证：

- G1、G2各自**重新初始化并终止算术编码区间**，长度与CRC各自计费。
- G2的概率模型仍可条件于G1的实际解码token；“两个独立终止码流”不等于“概率模型互相独立”。
- G1失败则不解码依赖其概率状态的G2；G2失败仍应能独立恢复G1。
- 多一次长度、终止、CRC及码块开销要从相同1024符号扣除，重新校准源前缀/分组/MCS。
- 必须比较针对同样误差分布优化的**单组熵码**、保守熵码与两组熵码，而不只比较raw。

这属于R3，**本文件不自动启动**。raw失败只说明本轮raw有限设计未建立收益，不是所有熵码UEP都不可能；raw成功也不是熵码UEP必然成功。

若之后需要“优于连续系统的鲁棒性”结论，再将P100k/Swin200k接到相同CSI权限：TX只读hat，RX读true；不能把接收网络错误SNR额外施加给基线。P若发送映射本来不依赖SNR，应保留该事实。该外部评价不属于先期机制GO门槛。
