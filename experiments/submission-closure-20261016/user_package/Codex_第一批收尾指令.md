# Codex第一批收尾指令：m10边界＋固定16图量化

## 任务边界

首篇停在单码字熵编码与raw两种实现。不再自动运行分层LE3/LE4、更多信道失配、瑞利衰落、组间功率、新网络或训练。

首先读HEAD和最新完成记录：有新完成项则核验后复用，不依据过时README重新执行。

## A. 完整第10尺度是否影响整尺度对照

1. 只读核查已有m10实际完整算术码流/长度。当前已审主接口只允许m4..m9；完整m10应为(10,0)、680个token，不能由raw8160 bit推断其熵码不可能装入。
2. 如无同身份缓存，使用原calibration1000，最多每源一次TX概率遍历，编码并实际finish到m10。保存完整bit流与真实长度，对已有全部q/r容量做只读装入检查。主协议最大容量4751 bit，实际从profile验证；不要引入LE2的1/3码率。
3. 原校准顺序前8源做独立源码RX，接收端不拿TX CDF或真实token。8源TX计入上面的1000，不重复。检查旧m9及旧部分终点码流一致，不误读第11尺度，不机械修改所有range。
4. 第一批不跑新的无线图像、不重评分校准图。交付min/median/P95/max、各容量可装图数、往返与旧接口回归。
5. 若0/1000可装，只能报告本集合没观察到；不能声称所有测试图永不可能装入。测试集合源码核查在校准规则冻结后另作。
6. 若任何图能装入，输出m10候选修正及实际影响清单。整尺度与部分尺度家族都应允许完整m10，旧候选保留；校准/受影响补帧预算先报告，第一批不自动开整轮校准。
7. 禁止看common500/new100的质量后选m10策略；新码流/profile/MCS产生新波形，不复用旧y伪装新观测。

## B. HiFi固定16图补上NeST-Com raw

1. 保留全部原16来源、N1024、13 dB。方法为raw、P100k、Swin200k、HiFi(Swin200k)。不是补19 dB熵码或改用旧Swin80k。
2. 查原生float32 raw输出及其接收来源。已知拼图中的raw可能是显示uint8，不能直接与其他三方法已发布float32分数混用。
3. 保留已有噪声：连续方法2001、HiFi后验23、数字raw6201。只有HiFi和Swin共享实际接收观测；不为统一seed重跑。
4. raw原生像素可用时：用原冻结DISTS、DreamSim、MS-SSIM设置给16对补48个分数，其他三列原48×3分数复用。另给全部4×16对补缺失PSNR，最多64个标量。新增上限112个标量，没有重训练或HiFi推断。
5. 找不到raw原生像素则报告精确缺口，不自动重建。可供后续选择的是“只恢复最多16个旧raw帧”或“四方法统一显示量化后另做一张标注表”；不要只量化raw。
6. 输出全16逐源分数、描述性均值/中位数、raw相对三方法的直接同源差值，不新增bootstrap，不宣称这是common500或总体显著性。

## C. 资料整理，不再加实验

- 汇总已有common500结果/源容量利用率/共享H800时延；raw整尺度没有DreamSim就用已有共同指标做机制表，不为大表补一轮4500图像对。
- 普通例图固定使用原16登记顺序前2张，失败案例另选并标为解释性例图；完整16图库保留。13 dB列名是NeST-Com(raw)。
- 从实际构建与权重整理VAR规模、分组件参数量、D_c训练设置、各工作点LDPC参数、数据官方split与内部角色。作者信息缺失留给作者填写，不编造。
