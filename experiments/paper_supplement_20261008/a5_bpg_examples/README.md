# A5 native256 BPG fixed examples

This independent entry consumes completed A3 native256 BPG RGB archives and the existing group02 display. It never calls a reconstruction model, compressor, physical channel, policy selector, or bootstrap. Adaptive-downsampling BPG is a separate method.

The sources `[4, 21, 24, 29]` and old five columns remain fixed. Three of these actual BPG cases are `SOURCE_UNFIT`; their gray fallback explicitly means no received frame. Source 29 has an actual parsed payload. All sixteen fixed BPG sources at 13 dB, including twelve source-unfit cases, receive new quality scores from original float RGB. Exactly the first measured repetition is used.

The four core fields are PSNR, LPIPS-Alex, DINOv2 ViT-L/14, and independent ConvNeXt source-prediction agreement. The original frozen FullSuite and ConvNeXt construction is imported by SHA. Only the existing core metric calls are used; mismatch/confidence calculations are omitted, and no old metric is recomputed. Sixteen reference preparations are separately counted. Successful per-source metric checkpoints are reusable; an unresolved reservation stops automatic duplicate work.

The original five-column per-image CSV uses the score row that matches the displayed float-image SHA, source ID, N, SNR, and seed. Empty old metrics are explicitly `MISSING`; the source column is `REFERENCE_NOT_SCORED`. HiFi's historical metric cache may not contain ConvNeXt. ResNet or classifier accuracy must never substitute for it. Original cached PSNR retains its original arithmetic precision. The combined CSV is long-form, preserving 0/1 agreement rather than disguising it as accuracy.

Actual collection confirmed eight missing ConvNeXt cells (four Swin and four HiFi). `fill_missing_convnext.py` is an independent, explicitly scheduled supplement: it loads only the same frozen ConvNeXt, verifies original float archives and the displayed-image hashes, and predicts only those eight missing reconstructions. Its cap is eight reconstruction predictions plus four original predictions; when the BPG score is already complete it reuses the four exact reference predictions after checking source hash and evaluator identity. It writes a new completed CSV under `missing_convnext/`, preserving the original missing-data CSV and all previously present values. Run it before final `export`; `render` needs no GPU. `prepare_missing_convnext.py --main-materials <materials_v2>` writes its separate request and execution list. No new full-suite evaluation is used for old methods.

The v2 collector accepts finite numeric strings from the continuous baseline, preserving their original text precision. It also leaves numerical runtime initialization solely to the frozen suite loader, avoiding a duplicate PyTorch interop initialization. Existing v1 runtime/materials are retained. Only the two newly prepared files in each execution upload list should be copied; the old figure files are verification-only dependencies.

BPG uses A3 seed 2001 with namespace `A3_DEVELOPMENT_TIMING`; historical digital outputs use 6201 and other historical baselines use 2001. Only Swin and HiFi share an actual observation. The figure and caption do not claim shared received noise across every method.

Prepare locally with `prepare_a5_materials.py --workspace <repository> --out <new-materials-directory>`. Its `execution.json` lists exact uploads and argv. Root runs CPU `collect`, schedules GPU `score` (six CPU threads, one GPU, 1800-second hard admission budget checked between sources), then CPU `render` and `export`. The existing shared visual lock prevents concurrent GPU consumers. Score retries use completed source checkpoints; unresolved reservations require examination. Only root launches remote jobs.

Outputs are under `paper/figures/a5_six_methods_N1024_13dB_group02`: 600-dpi PNG, PDF with vector text and original image panels, SVG with editable text, fixed display NPZ, new sixteen-source BPG float scores, original five-column metrics, combined per-image metrics, explicit missing-data list, provenance collection, English caption, and completion. Figure render is independent of missing historical metrics. Actual visual QA is required after root runs it.

## Separate adaptive-downsampling comparison

It imports the unchanged adaptive source codec and qualified physical link. All15 source-search capacities and receiver codebook entries remain present, because pruning them could change the frozen search or false-header behavior. The extension selects only the already-frozen13-dB profile for transmission.

The receive job owns a separate32-call ledger, two2-thread CPU workers on10–13, and a maximum1800-second window. It does not write A1 request/runtime/ledger files, requalify the link, or use GPU models. An explicitly empty development-native-stream cache index is configuration, not a scientific completion claim; source candidates are actually encoded and subsequently reused only from their own completed receipts. Source selection has at most208 cases/source. The receiver decodes actual accepted payload bytes. Source-unfit gray is distinguished from a received-frame failure. `prepare_adaptive_fixed16.py` writes the bounded request and uploads.

`adaptive_cached_examples.py` consumes only the actual wait-zero16-frame completion. CPU collect/render and a separately scheduled GPU score export to `paper/figures/a5_adaptive_six_methods_N1024_13dB_group02`, preserving the native256 figure.
