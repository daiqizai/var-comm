# 同起点：只更新R与联合更新E/R

## 状态与问题

**准备，未启动新GPU训练。** 不中断当前冻结发送器六臂实验，不把本对照当新的论文机制。父点训练审计表明：E仅有7000更新，其中图像阶段20000次曝光覆盖15197个不同源图，其余4803源图只接受过表示监督。single/no-history末段校准仍改善，conditioned近乎持平。既不能假设都已收敛，也不能保证多训会改善。

问题是：相同已训练通信起点、相同进一步数据与更新机会下，让通信发送器继续学习是否减少其引入的图像损失？多尺度条件读取的相对收益是否随此改变？

## 配对设计

三结构`single_pass / multiscale_no_history / multiscale_state_history`，起点**都是原204×30 single父点**，与wetok-innovation-r1这三臂的初始化逐权重一致。并非分别从三个旧geometry自有最佳模型开始，也不从当前R已更新1000/2500的最佳点开始。

- R-only：只读复用已有冻结E控制的完整5000更新、同fresh Adam初始规则、相同数据/翻转/SNR/噪声与校准。
- Joint：只增加E参数梯度与optimizer更新，R也按原规则训练；不加层、不换表示、不引入新loss、功率分配或反馈。
- 初始架构与权重不变，可训练参数数目因此增加；不声称等训练FLOPs。新波形随E更新变化，**不是同y比较**，是同源、同N/E、同噪声和更新机会的通信映射比较。

当前阶段只准备Joint代码；启动前冻结实际5000控制里程碑、校准审计和SHA，核对完整训练机会。控制尚未完成时不以1000替代5000，不改历史SHA放行。

## 不变项

WeTok Encoder/量化器/Decoder、LPIPS模型全部冻结。全局204×30＝6120实坐标，0 header＋3060 complex uses，总能量6120、平均复能量2，每实维噪声1/gamma。名义SNR双方可见，训练1/4/7/13/19，无类别/caption/反馈/真实接收历史。

原loss为MSE＋0.01 LPIPS＋0.01 bit BCE＋0.01 state，均沿用原连续均值接口；DINO不训练/选模。fresh AdamW，LR1e-4，betas .9/.99，weight decay1e-4，clip1，有效batch4/micro1；global data从7000接续。新臂5000更新先以1000里程碑检查，与控制相同0/1000/2500/5000完整校准选模、每500监控。选中0若发生必须报告，不虚构训练收益。

发送时每有效batch4只调用一次E。四个micro的R与图像loss先在独立的接收波形梯度边界累加，再将合计梯度显式反传到原发送图，E反向也只执行一次。这是链式法则的精确向量-Jacobian积，不是ST或省略E梯度；中间`detach`必须与末端显式反传配对。冻结视觉参数不妨碍图像梯度回到通信E/R。CPU检查核对micro累积和整batch梯度、E反向调用次数，以及完全关闭E更新时与旧R-only的结果逐位一致。

仅打开E参数梯度标记时，PyTorch对非连续3D输入的线性层可能从batched matmul切换到folded matmul，引起FP32末位差；已在本机定位，未修改旧Encoder、权重或物理约定。初始化权重SHA仍严格相同，冻结模式仍逐位回放旧控制；Joint初始波形沿用已有1e-6回放容差，额外用FP64核对相同数学映射，不声称不同梯度标记下的FP32波形字节完全相等。详见`numerical_gradient_note.md`。

## 比较和解释

最重要是每个结构Joint对R-only，以及Joint条件对Joint无历史/单次。后续同时保留当前强数字、WeTok数字和感知Deep，不把旧训练规模不同的强系统说成等参数或等历史控制。

no-history在训练中有4/8辅助监督，但最终图像不依赖这两个计算；部署可仅运行16尺度读取，不能强迫它多算无用阶段来制造时延优势。本三臂主要隔离E是否训练；若Joint条件出现图像增量，仍需对应的Joint纯全网格迭代控制，不能仅凭胜过单次/无历史接收就排除“多算几步”的解释。

最终图像PSNR/SSIM/LPIPS/DINO、严重失真、推理时延和GPU小时都要报告；原100图仍development。按源图平均噪声后配对统计，不根据development选择发送模式/步数，不访问新holdout。若仅增加训练有用而多尺度无独立收益，应明确这样报告。

新增训练尚未GPU测速，不能沿用R-only时间当作Joint费用；真实无更新梯度/速度检查要在当前GPU任务自然退出且无其它计算任务后进行。只有当前RX研究的实际结果与完整控制资格支持继续时再激活，不自动并行开跑。
