## 先静态检查，再加载模型

阅读官方README、demo.py、compression/sender.py、compression/reciever.py、compression/util.py、utils/arithmeticcoding.py、infinity/utils/dynamic_resolution.py。

确认官方适配权重、许可和独立环境。不得运行train.sh，不得用未适配Infinity基础权重冒充ARPC，不改动现有NeST-Com依赖。

公开分辨率表已提供方形 `pn='0.06M'`：256×256，七个尺度1/2/4/6/8/12/16。保留其官方量化分组与推断设置，先验证冻结权重可用；不要上采样到1024，不套NeST-Com十尺度表。

特别审查：
1. BLIP由原图生成的描述必须真实传输并计费；不能免费给RX文本或embedding。
2. trans_list/help_list的模式、边界和长度必须能从紧凑自描述码流恢复；不要免费传Python列表，也不要用JSON/Pickle的巨大开销削弱基线。
3. 接收端只有真实码流、profile和共享模型；检查gt命名参数是否实际使用，不凭名称指控泄漏。
4. 前缀接收时只能解已传尺度，不允许先解全尺度再挑前缀。
5. 原demo的bpp分母写成1024²；本次按实际256²计算，额外区分作者视觉bit计数与独立payload总bit。

## 固定八图

从原cal1000的规范source ID按
`SHA256('ARPC_EXT_CAL_V1|' + source_id)`排序取前100，第一批只用前8。
锁定来源与RGB256像素hash，不按图像内容/结果换样本。不要读common500/new100来选参数。

每源测试第1/4/7尺度终点：24次独立源码往返。最多8次图像描述与8次source概率遍历；参考与独立接收生成合计最多48次。全部在无噪声文件传递条件下完成，无线图像帧为0。已有成功结果按身份复用，不为了凑表重跑。

独立接收进程读取文件，重算文本特征和源码概率。输出保存后再用真值审计，不用真值恢复。固定生成seed与原生采样超参，不取多次生成中的最佳值。

输出码长分解：文本、文本长度、视觉bit、模式flag、分段边界、其他元数据、终止/对齐。只在真实序列化后计算1245/2520/4751 bit容量下能装入什么，不按理论交叉熵或列表展示长度宣称装帧成功。
