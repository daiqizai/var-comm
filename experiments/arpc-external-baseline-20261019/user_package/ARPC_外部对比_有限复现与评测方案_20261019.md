## 0. 执行决定

只增加一个最接近的外部生成式源码系统：**ARPC + LDPC–QAM (adapted)**。

先完成 A0 源码/资产核查与 A1 八图无噪声编解码资格检查，随后交付并停止。只有输入、文本与辅助信息、独立译码和实际码长均合格，才另行批准 A2 校准和 A3 正式对比。

当前 NeST-Com 正文、同版本利用率核对和图表整合继续，不等待一个无期限的 ARPC 复现。分层保护、更大 SNR 失配、功率分配、tokenizer/VAR/P/Swin 新训练、第二个外部模型全部不启动。

这项比较回答：在相同的逐图无线资源下，NeST-Com 与一个外部逐尺度生成压缩系统有何质量与计算取舍。它不是隔离“部分尺度”单一因素的消融，也不是用来保证本方法获胜。

## 1. 已核实的实现事实与未知事项

### 1.1 已核实

1. ICLR 2026 官方记录列有 ARPC；它包括逐尺度压缩、生成补全、条件熵编码和分组掩码比特分配。官方 README 提供经过其训练的模型和推断入口。[R1,R2]
2. 公开 demo 默认 `pn='1M'`，但 `infinity/utils/dynamic_resolution.py` 已有方形 `0.06M` 预设，像素尺寸为 256×256；尺度边长为 **1,2,4,6,8,12,16**，共七尺度。不得把 NeST-Com 的十尺度表套进去。[R3,R4]
3. README 说明测试图像描述由 BLIP 生成；源码用文本编码器为发送端概率模型和接收恢复提供条件。接收端不能免费获得由原图生成的描述。[R2,R5,R6]
4. `compression/sender.py` 返回嵌套的 `trans_list` 和 `help_list`：每组根据长度选择压缩或原始 bit，并保存模式标志；其 bpp 计算使用 `1024*1024`。这不是已经验证的、完整自描述无线文件格式。[R5]
5. `compression/reciever.py` 的实际译码逻辑根据恢复出的 token 推进条件状态。参数名带 `gt` 不自动证明泄漏；需要审查实际读取路径和独立进程输入。demo 先解全部尺度、再展示不同前缀的做法也不宜直接当作仅收到前缀的接收端。[R3,R6]
6. 既有 NeST-Com 主比较为 RGB256、N1024、4/10/19 dB；19 dB 使用 T1-C 修正版。P100k、Swin200k、BPG 已有对应来源结果。HiFi 小表是另一组 fixed16/raw/13 dB，不能混入本次。[P1,P2]

### 1.2 本次没有确认

模型权重此刻是否可下载、授权条款是否满足用户用途、目标服务器的兼容性、冻结权重在 `0.06M` 下是否正确工作、完整容器的开销、跨独立进程实际往返是否通过，以及任何 ARPC 的新质量结果。

“代码有 256 预设”不是“256 下模型已复现”；“源码是列表”也不是“原论文造假”。本方案针对可核实的独立传输接口建立证据，不作作者动机判断。

## 2. 范围、阶段与计算上限

**900只是最终评价帧数，不是全部复现成本。**满额 A2b+A3 为18,900逻辑方法帧，另最多24资格帧。每帧通常含header/body两次包译码，另行计数。ARPC自身的图像描述、概率计算、算术解码和生成调用也分别计数，不能被“仅推断”掩盖。

以上都是上限而非必须跑满。相同物理发送、相同接收结果和相同生成状态可以精确复用。缓存复用不改变统计分母。超过上限、需要新增模型训练或大量源码重构时，先提交原因和新增量，不自动扩大。

A0/A1设一个可用资源窗口，交付完成结果或明确阻塞，不无限调环境。窗口时长先根据实际排期登记，本方案不根据B300型号承诺吞吐。

## 3. 数据与随机性

### 3.1 固定来源

- 校准池：原 `cal1000`，不用 development/common500/new100 选 ARPC 配置。
- A2a 的 `cal100`：对原cal1000的规范source ID计算 `SHA256('ARPC_EXT_CAL_V1|' + source_id)`，按哈希排序取前100；A1取该清单前8张。
- 正式评价 `external_common100_v1`：对原common500的source ID计算 `SHA256('ARPC_EXT_EVAL_V1|' + source_id)`，排序取前100。在运行ARPC和检查逐图赢家前写入清单。它不是历史的new100。
- 不按是否能装入、内容类别、图像复杂度、某方法得分或视觉效果挑选/替换样本。
- 这100张来自已被历史评价的来源集合，描述为固定来源子集，不称全新盲测。

### 3.2 图像输入

直接使用当前任务登记的RGB256标准图像；ARPC仅作其所需的[-1,1]变换。不要从原始大图重新裁另一个区域，也不要先上采样到1024后仍称等输入256比较。

采用官方 `ratio=1.000, pn='0.06M'` 的scale schedule，并保留该预设下作者代码的量化分组规则。核对 checkpoint load、位置/尺度信息、输出形状及全尺度恢复。若权重不能可靠支持这个设置，标记 `BLOCKED_NATIVE_RESOLUTION`，不偷偷用不同任务补齐表格。

### 3.3 噪声与生成随机性

- 无线噪声沿用项目现有公开标准噪声函数和原登记的cal/eval种子，实际从注册文件确认，不只复制整数种子。
- 新ARPC有自己的发送波形，不能复用NeST-Com接收波形y；可在同source/seed上使用相同标准AWGN变量。
- ARPC保留作者原生生成方式，不为了方便改成NeST-Com的greedy。CFG、温度、top-k/top-p先按原生配置固定；必须变更时在校准前登记。
- 每source使用固定、可复现、与结果无关的生成种子。三次噪声不挑最佳生成样本；固定生成种子用于隔离信道随机性时，在统计说明中写明。精确缓存键包含全部生成状态。
- source ID只用于重现来源/噪声/随机种子，不允许映射到免费图像描述或视觉token。

## 4. A0：先建立真正可发送的源码边界

### 4.1 模型身份

必须使用官方发布的ARPC适配权重及其量化器/解码器，不能拿未适配的Infinity-2B基础权重冒充ARPC。记录checkpoint哈希、匹配键、文本编码器与BLIP的具体版本。

独立环境运行；不修改现有NeST-Com训练/推断依赖；移除demo的机器绝对路径与GPU硬绑定应以独立适配补丁完成。保留上游文件及变更差异。禁止自动执行train.sh。

### 4.2 文本条件

主比较保留作者原有图像描述路线：发送端在标准化后的同一张RGB256上用固定BLIP生成一次描述，不访问类别标签、人工标注描述或外部模型API。

优先使用作者已有的文本序列化/无损压缩方式（若能定位）。没有时，采用在A1前冻结的可逆UTF-8文本封装与通用无损压缩；记录压缩器、参数、文本长度字段和结束信息。收到的字符串需逐字节恢复；文本特征由接收端自己的冻结文本编码器重新计算。

不能默认传整个浮点文本embedding。也不能因为文本太长就将其免费共享、按结果换短描述、将所有描述置空后仍叫原方法。使用固定空提示的变体只能作为另行标记的消融，默认不启动。

### 4.3 嵌套视觉码流

`trans_list/help_list`中的实际bit、模式标记、每段边界必须能从有限字节串恢复。若边界可由作者的解码规则推得，需要实际证明；不能假定Python列表边界不占信息。

优先寻找已有作者容器；若确实只有嵌套列表，设计一版紧凑、确定、可逆的位级封装。模式flag、必要分段长度、对齐和尾部都计入。不得用JSON/Pickle的膨胀大小故意削弱基线，也不能将接收端所需的分段长度留在免费Python对象中。

审查原模式切换：原始块长度已知时无须再传冗余长度；压缩块只有长度不可推得时才加紧凑长度描述。记录简洁容器与作者公布视觉bit计数的差额。若自行增加的容器成本主导了结果，应提交技术原因并暂停“原生ARPC无线性能”归因；不能用自创低效封装当它算法低效的证据。

### 4.4 接收端允许的输入

允许：接收到的码流、付费profile、预先共享的架构/权重、已知图像尺寸、固定公共随机设置和接收端信道信息。

不允许：原图、源端真实token、没有传输的尺度、TX概率/CDF、源端缓存的prompt embedding、未付费文本/模式/长度列表、利用正确token识别失败或选择重建。

`decoding()`中的gt参数若实际未使用，可在独立包装中去除；若任何路径读取它，应改成实际解出的前缀，或停止该路径。仅凭变量名不能宣布泄漏。

## 5. A1：八图原生能力与独立往返

### 5.1 三个代表终点

在官方七尺度256预设下，每源测试第1、第4、第7尺度终点，共24个prefix-case。它们是“浅/中/完整”资格测试，不是新码率范围；正式候选仍允许全部七个完整终点。

### 5.2 资格流程

1. 用官方权重和冻结配置取得发送端token及概率，仅供发送和独立审计。
2. 将指定前缀、文本和全部必要辅助信息序列化为文件，记录精确bit数和hash。
3. 在新的接收进程中，清除发送端模型状态/概率缓存，仅通过文件和共享模型还原文本、模式、边界及前缀token。
4. 译码只处理实际已发送的尺度，然后调用ARPC自己的生成过程补其余尺度。不能先解出全部真实尺度再挑一个前缀来伪装部分接收。
5. 接收结果保存后，由隔离的审计进程核对token、字符串、边界和确定性重编码。使用同一生成种子的本地参考与独立接收输出核对，像素非逐位一致时记录误差及来源，不偷换容差。
6. 对文本、长度和模式字段做CPU损坏/截断测试，确认解析器不会自动向发送缓存补信息。资格损坏测试不是实际信道误码实验。

原生全尺度/截断恢复的视觉质量应能排除明显加载错误、数值崩坏、全部常数图和错误预处理；不要求它必须赢NeST-Com。若结果偏弱，先核对官方设置，不在测试图上反复调整到想要的结论。

### 5.3 两种码率表，必须同时交付

- `author_visual_bit_count`：作者代码统计的视觉stream+模式信息，准确命名。
- `standalone_payload_bits`：真正独立传输所需的视觉+文本+边界+辅助+对齐总bit。

二者分母一律采用实际源图H×W。正式256任务不能继续除以1024²。第一张表帮助解释复现差异，第二张表才进入无线预算判断。

根据所有合法终点长度，报告在1245/2520/4751 bit容量下的装入情况。这只是当前三档NeST-Com容量锚点；不是强迫ARPC以后采用这三种MCS。

### 5.4 A1交付与停止

至少输出：
- 权重/环境/官方配置及补丁记录；
- 八图来源与像素身份；
- 24例独立往返结果；
- 七终点源码长度（已编码即可复用）、文本/flags/边界成本分解；
- 当前容量下fit/no-fit表；
- 原生恢复和独立恢复的资格记录；
- B300/其他实际资源的显存、单源处理时间和扩展预算估计；
- `READY_FOR_CALIBRATION`或具体阻塞说明。

A1结束停止。少数/全部图在某低容量下装不入本身是可报告结果，不应因此删除来源。只有复现正确性、任务不匹配或预算工程成本使比较无法忠实解释时才列为技术阻塞。

## 6. 无线封装与资源约束（A2前冻结）

建议为ARPC建立独立公开profile目录，复用当前数字物理层的已验证实现，而不改已产生成绩的NeST-Com profile。

对于每个合法布局：

\[
N=1024,
\quad N_h=68,
\quad N_b=956,
\quad q=\log_2M,
\quad n=956q,
\quad C=k-13-16.
\]

定义完整自描述载荷：

\[
b_{\mathrm{payload}}=
 b_{\mathrm{text}}+b_{\mathrm{text\ length}}
 +b_{\mathrm{visual}}+b_{\mathrm{mode}}
 +b_{\mathrm{segment\ boundaries}}+b_{\mathrm{other}}.
\]

已包含的字段不得双计，未包含的字段不得漏计。装帧约束为：

\[
b_{\mathrm{payload}}+13+16\le k.
\]

外层正文为“总长度13 bit + 自描述payload + 已知填充 + CRC16”，再经实际5G NR LDPC和QAM发送。profile指定合法模型模式、分辨率、实际终点和MCS等；12-bit目录足够与否用实际枚举核查，不能私下扩大免费目录。保留真实header译码、CRC及合法性检查。

沿用当前标称平均星座能量Es=2和AWGN定义；不是每帧严格等能量。正文码率取实际k/n，以后端资格结果为准。成功恢复payload后才运行文本/视觉源码译码；header、body或源码失败输出同一固定失败图，所有帧计入。不对损坏算术流使用raw KEEP，不引入重传/分层。

最低完整终点也装不下时：记录`SOURCE_NO_FIT`，发预先登记的null profile及规定填充，保持N/能量口径及失败分母。不得无声改图像尺寸、增加带宽或免费传文本。caption-only方案不属于默认ARPC主复现。

公共目录只包含与图像无关的规则，不可保存每张评价图的描述或token。

## 7. A2：给ARPC自己的选择机会

### 7.1 候选范围

以当前NeST-Com熵码使用的三种调制与四个标称码率为共同数字候选族：

- M∈{4,16,64}；
- r∈{1/2,2/3,3/4,5/6}；
- 原生ARPC七个完整尺度终点作为最大目标。

最多7×12=84个目标策略；按实际容器长度回退到能装入的较短原生完整终点。所有完整终点包含全表示，不仅选择对NeST-Com有利的截断深度。不向ARPC移植NeST-Com的部分尺度算法后还叫原生ARPC。

每图生成一个固定描述，不按SNR改写。CFG/温度等不加入大网格。若采用其他作者推荐配置或新增合法MCS，必须在校准前登记并记录为何必要，不能看评价成绩后修改。

### 7.2 预筛（cal100）

在固定cal100上取得实际payload长度及最多七种干净前缀恢复质量；已有8源按完整身份复用。使用现有、匹配的码块可靠性表作有限预筛。零观测错误不等于真实BLER为零；未经覆盖的布局不能当作无误链路。

预筛采用与NeST-Com相同的DINOv2-L选择目标，同时保留PSNR/LPIPS诊断。它只是候选提名，不是无线成绩。

每个SNR最多提名两个不同策略进入真实链路校准；包含最佳估计项和可能因可靠性/码率取舍改变排名的竞争项。若预筛不确定性无法用两项覆盖，应报告并另行决定预算，而非静默淘汰强候选。

### 7.3 实际校准（cal1000）

对锁定候选在全部原cal1000、4/10/19 dB、每源3次原校准噪声上实际发送和接收，保留全部失败。

\[
1000\times 3\times 2\times 3=18,000
\]

是上限；候选少或发送完全等价可以减少计算，不改逻辑分母。NeST-Com原策略保持冻结，不能为对付ARPC在评价集上重新选择。

源码只需按每源遍历一次，不为每个SNR/MCS重复概率计算；干净图像恢复只有在实际接收token/text及生成随机状态完全相同时可复用。CRC接受但payload不等于发送真值时，必须让实际错误进入恢复，审计真值不得触发免费纠错。执行中的程序错误与科学解析失败分开记录。

最终每SNR按同一DINO目标选一个赢家，冻结checkpoint、源码格式、MCS/目标/回退、caption、随机设置和失败规则。完整校准不是穷尽所有ARPC变体，论文按有限候选报告。

A2运行前必须依据A1实测吞吐确认B300窗口和7000个可能的source/endpoint上界等实际恢复成本。若资源不支持，不把cal100预筛赢家悄悄当作“与cal1000同等充分校准”的最终外部基线；可交付明确标记的探索比较或暂停。

## 8. A3：100图的正式外部比较

使用已锁定的 `external_common100_v1`，在4/10/19 dB、每源3次原评价噪声下评价冻结ARPC，共900逻辑方法帧。不按成功情况换图、不挑SNR、不挑生成seed。

同一100源上汇总：

| 方法 | 数据来源 |
|---|---|
| NeST-Com (entropy-coded) | 从既有common500逐源记录提取；19 dB用T1-C修正版 |
| ARPC + LDPC–QAM (adapted) | 本次新增 |
| Latent-space JSCC (P100k) | 同100源最终逐源记录 |
| SwinJSCC (adapted,200k) | 同100源最终逐源记录 |
| Adaptive BPG + LDPC | 同100源既有逐源记录 |

不能直接把500图平均值与100图ARPC平均值放同一行比较；不能把900帧当900个独立样本。若对应逐源缓存不可用，先报告缺口，不推断或重造旧数值。

### 8.1 指标与统计

沿用冻结的PSNR、LPIPS-Alex、DISTS、DreamSim、DINOv2-L、ConvNeXt来源预测一致率、MS-SSIM，原预处理/权重一致。

既有方法逐源分数复用，只给新ARPC输出计算新分数。同一输出hash+参考图+metric版本可缓存。所有方向完整报告，不为了结果换指标。预测一致率不称语义完全忠实。

每源先平均其三次信道实现，再计算100源等权均值。对主比较“NeST-Com − ARPC”做新的来源配对95%区间；原500图区间不沿用到100图，也不相减边际区间。新增统计固定10000重采样、seed2026100701，一次正式生成后归档；它不覆盖训练随机性、历史选题过程和所有架构不确定性。

其他既有方法可提供同源描述性均值及由当前100源计算的点区间；不自动新建大量两两检验。所报区间为逐点，未经多重比较校正，不能称“所有条件总体显著最优”。

### 8.2 论文交付

优先一张单独的100图表或小图，不把ARPC100曲线塞进原500图主图。标题中明确“100-source matched comparison”；原500图主结果保持完整。

一组固定来源的原图/ARPC/NeST-Com实际重建可以辅助说明，全部100源记录可查；不选择最有利的生成样本。不重新跑HiFi，也不把13dB fixed16与本次合并。

若结果有优劣交叉，按指标和SNR报告。若ARPC全面较好，也保留比较并调整NeST-Com的系统优势表述；内部同先验机制结论仍需独立评价。

## 9. 成本与设备

ARPC与NeST-Com不要求参数量相同，但要披露冻结先验规模、文本条件、是否训练、预处理及后验方式的差异。本次结果是系统比较，不归因为唯一截断机制。

两台B300先用于模型资格和独立TX/RX进程；一台也可分时完成。不要一开始部署跨机张量并行或新训练。提前准备容器、权重、数据和可恢复缓存；根据实际秒/源估算A2/A3，不承诺具体总工期。

A1记录显存和处理时间只是计算规划，不与旧共享H800时延作倍率比较。正式相对时延若需新增，单独登记同一设备上当前NeST-Com与ARPC的成对测量；包含图像描述、文本编码、码流打包、LDPC、源码解码与图像恢复，排除指标和磁盘，不能免费复用源码缓存。该计时不是本批自动任务。

## 10. 决策规则——不以本方法获胜作为关口

- `READY_FOR_CALIBRATION`：官方权重可用，256设置合格，独立往返成立，所有必要bit明确，恢复行为忠实，资源预算可估计。
- `BLOCKED_WEIGHTS_OR_LICENSE`：模型/授权无法满足；明确缺哪个资源，不伪装为模型性能差。
- `BLOCKED_NATIVE_RESOLUTION`：不能在同输入任务上忠实运行；不偷偷扩大分辨率。
- `BLOCKED_STANDALONE_STREAM`：无法在有限容器内独立恢复；保留直接原因，不将源码列表当真实无线输出。
- `NEEDS_FAIR_SERIALIZATION_REVIEW`：自建元数据封装主导成本或严重偏离作者方法；先审封装，不用不合理开销削弱基线。
- `RESOURCE_REESTIMATE_REQUIRED`：实际吞吐超出窗口；报告净开销，不偷偷缩来源或候选。
- `COMPLETE_MATCHED_COMPARISON`：已冻结策略并完成全部900逻辑帧及同源统计；无论谁赢都交付。

如果无线适配无法在合理范围内完成，可以交付独立的无噪声源码率—质量参考，但它不进入无线曲线，不称等通信条件的ARPC；免费文本只可作明确标注的理想辅助信息诊断，不称公平主基线或数学性能上界。换另一外部方法需另行决策，不自动启动。
