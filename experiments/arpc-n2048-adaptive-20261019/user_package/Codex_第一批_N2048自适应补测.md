# Codex第一批：N2048双方法低SNR自适应补测

请先阅读同目录《NeST_Com_ARPC_N2048_低SNR自适应补测方案.md》。

当前核查快照是980d74c。新的目标不是传完整表示，也不是重启分层保护，而是：两种方法都在N2048、4/10dB根据校准选择较短合法前缀和更合适的MCS。

## 第一批只完成这些

1. 读取最新RESEARCH_STATUS，若出现更新则核对实际变化，不能覆盖已有新工作。原N1024、旧N2048固定full、所有历史失败和其他研究分支不动。
2. 审计pair_protocol.py和pair_link.py的固定K4780/N5736/Q6及ENDPOINTS={0:10,1:7}。在新目录设计按实际付费profile参数化的q/k/n/端点；NeST支持原(m,K)端点，ARPC支持原e1–e7。
3. 两片等保护、同MCS、两片全部恢复才解同一个已结束源码对象；不是基础层/增强层独立源码，不加KEEP/UEP/功率/ARQ。
4. 先读取已登记的cal100、cal1000和external_common100原源码与评分缓存。不要先重跑BLIP、tokenizer、VAR/Infinity或整批评分。列出source/endpoint级净缺口。
5. 对共同12种q/r布局，用真实k和每片13+16+96bit开销及字节取整计算两片源码容量。交叉核对QPSK2/3=2288bit、16QAM2/3=4848bit、64QAM5/6=9296bit。这是容量不是成功率。
6. 为每个来源和策略执行实际码长回退，记录目标、实际端点、码流/对象bit、片长和余量。caption及封装开销必须完整计入ARPC。
7. 公开profile必须携带实际端点和MCS，RX不得获取TX真值。固定96bit扩展方案和全对象CRC所绑定内容；若增加开销，重算所有容量。旧19dB锚点只有经实际字节及接收等价证明后才复用。
8. 输出完整候选依赖表、已有BLER/双片可靠性证据覆盖和不确定性、优先资格单元、净资源计划。已有单包0失败不能视为新双片对象必成功。

## 后续规划范围，第一批不要自动执行

- 资格：最多24对象/48子帧，并配合CPU协议测试。
- cal100有限预筛：两边同样的MCS权限与DINO目标；缺失恢复按真实对象去重。
- cal1000确认：每方法×4/10dB最多2个候选，三次噪声，最多24000逻辑对象/48000子帧；既有完全相同事件优先复用。
- 固定external_common100正式评价：两方法×4/10dB×3噪声=1200逻辑对象/2400子帧，原七指标和来源级配对统计。
- 19dB仍是已完成的固定完整表示参照，不能直接标成“重新校准的全SNR最优策略”。
