# 发送分组形状候选：准备，不启动训练

## 问题与假设

当前2500检查点在noiseless/19dB仍有明显学习映射损失。只读诊断还显示：153×40线性skip的秩为4896，额外8个通道方向上的实际信号能量很弱。这只提供发送映射/可学习性的线索，不是完整非线性码的容量界，不能直接称“20%带宽浪费”或保证全行秩更好。

准备一个有限、可否定的比较：保持同一8192-bit原生Fq源、continuous接收接口、视觉骨干、loss、N3060/E6120与2层192维通信骨干，只把全局6120实坐标的组织从**153×40**改为**204×30**。两者都不是按语义尺度分包，全部接收阶段仍读完整y。

204×30的空间/通道线性因子均可行正交初始化，线性skip秩可达到6120。原代码只覆盖通道数≥32的列正交扩展，不能不改初始化就把通道设为30；新候选使用32维正交矩阵的前30行，正确构造30×32映射。旧153×40构造保留原实现，不改变已运行代码。

## 对照与限制

- 计划仍需要两种geometry各自的single/no-history/conditioned，源、数据/增强/SNR/噪声、训练机会和校准规则必须匹配；不能只训练一个有利组合。
- 可共享形状相同的神经参数初值；几何相关张量的形状不同，不能伪称全部参数初值或参数量完全相同。
- 接收memory从153变为204，参数量和计算量也会变化，必须实测并报告；若有收益，它首先是geometry实现包的效果，不直接全部归因于秩，也不证明next-scale首次贡献。同geometry内条件/无历史比较仍负责结构归因。
- 旧轨迹只有在初始化、阶段配方、实际数据/噪声与选择资格逐项可验证相同时才可复用；不能用不同历史的旧best随意替代控制。是否复用及实际训练日程须在正式启动前锁定。
- 不同时改LPIPS权重、输出接口、功率分配、反馈或视觉模型，不搜索一串shape来选漂亮结果。

## 当前实现范围

CPU检查已通过：旧153×40控制的参数与发射/接收前向和原实现逐元素一致；204×30的两个线性因子均行正交、线性skip秩6120，输出仍3060复符号/平均复能量2，图像fixture梯度到E/D非零。控制2895944参数，候选2927358参数，不能称严格等参数/等计算。总30项CPU测试通过，尚无候选GPU或真实图像性能结果。

仅新增geometry_candidate.py及CPU检查。旧153×40需与原InterfaceJSCC在同seed下参数和前向完全一致；204×30需验证形状、正交因子、功率、source/RX边界及图像梯度。尚未进行该候选的真实GPUprofile、训练、校准、开发评测或独立验证。

这些检查是工程准备，不是要求无训练质量先胜出的gate，也不是已经证明该候选有效。当前九臂仍按原配置向5000推进，结束后先根据完整证据决定是否启动这个新比较；不会因为候选已写好就自动切换。
