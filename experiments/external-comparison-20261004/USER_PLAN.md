# 外部方案对比执行单（2026-10-04，v2）

> **要回答的问题**
> 1. 在**同样的绝对信道符号数**下，其他方案是否也会出现"关键物体丢失、身份改变"这类语义错误？
> 2. 资源增加到多少时，你的方法的语义错误会明显减少？
>
> **原则**
> - 所有方案统一用 256×256 的图像，按"每张图的复信道符号数 N"对齐，**不只是按 CBR 对齐**；
> - 使用同一组预先固定的样例，**不挑图**；
> - 外部方案的资源点无法精确对齐时，如实标注实际的 N；
> - **优先复用 `projects/` 下已经跑过的外部方案**（代码、权重、配置、结果），确实没有或无法对齐时才重训。

## 第 −1 步：检索 `projects/` 下已有的外部方案（最先做，约半天）

用户此前已在 `projects/` 下跑过 SwinJSCC、SGD-JSCC 等多个外部方案。在做任何新训练之前，先完整盘点。

### 1. 检索范围

- `projects/` 整个目录（含子项目、旧实验目录）；
- 本仓库中已有的外部基线目录：`experiments/external-baseline-positioning-20260916/`、`results/external_baselines/`；
- 若有单独的数据盘或权重目录，一并检索。

### 2. 检索方式（示例，按实际环境调整）

```bash
# 按方法名检索目录和文件名
find projects -maxdepth 4 -iname "*swin*" -o -iname "*sgd*" -o -iname "*adjscc*" \

  -o -iname "*witt*" -o -iname "*mamba*" -o -iname "*diffjscc*" -o -iname "*dit*jscc*"

# 按内容检索（代码、配置、日志、README）
rg -il "swinjscc|sgd-jscc|sgdjscc|adjscc|deepjscc|diffcom|hifi-diffcom|ntscc|witt|mambajscc|diffjscc|dit-jscc" projects

# 权重文件
find projects -type f \( -name "*.pth" -o -name "*.pt" -o -name "*.ckpt" -o -name "*.safetensors" \) | sort

# 结果文件
find projects -type f \( -name "*.csv" -o -name "*.json" -o -name "*.npz" \) -path "*result*" | sort
```

### 3. 盘点表（每个找到的方案一行，写入 `reports/external_inventory_<日期>.md`）

| 字段 | 说明 |
|---|---|
| 方法与版本 | 例如 SwinJSCC（官方仓库某 commit）、SGD-JSCC（论文协议版） |
| 位置 | 代码、权重、配置、结果的路径 |
| 训练设置 | 训练数据集、分辨率、训练损失（MSE / LPIPS / 其他）、训练 SNR |
| 资源设置 | CBR 定义与取值，换算成 256×256 下的复符号数 N |
| 信道与功率 | AWGN / Rayleigh；功率归一化方式 |
| 附加信息 | 是否使用文本描述、边缘图、类别等附加信息，是否计入开销 |

### 4. 可复用程度判定

| 等级 | 条件 | 处理 |
|---|---|---|
| A：直接复用 | 256×256，N 可对齐到 1024 或 2048，有对应 SNR 的权重 | 直接在固定样例与 development 上评测 |
| B：可调整复用 | 权重存在，但 N 或 SNR 不完全对齐；或分辨率不同但可缩放 | 选最接近的资源点评测并标注；或在已有权重上微调到目标 N |
| C：只能参考 | 资源相差过大，或依赖未计开销的附加信息 | 只作为定性参考，不进入同资源主表 |
| D：需要重训 | 没有可用权重，或设置完全不符 | 按原论文配置在 256×256、目标 N 下重训 |

**关于 SGD-JSCC 的特别说明**：仓库历史记录显示，此前按其论文协议跑过，使用了**免费的文本描述**，且 N = 9856。文本描述属于附加信息，若不计入开销，不能和本方法放在同一张同资源主表里。处理方式二选一：
- 将文本描述按实际比特数计入资源，并换算到对应的 N；
- 或运行不使用文本描述的版本。

两者都做不到时，按 C 级只作定性参考。

## 第 0 步：用已有结果看更大的 N（零成本）

**做什么**：从已发布的结果里，取同一组固定样例在更大 N 下的重建图，拼成一张图。

- **你的方案**：数字 VAR（N512、N1024，以及旧链路的 N3060、N4084）、方法一（N512、N1024）；
- **连续方案**：P512、P1024、P2048、P3060、P4084；
- **外部方案**：第 −1 步中已有重建图的外部方案，按其实际 N 放入；
- **SNR**：7 dB 和 13 dB。

**要回答的问题**：鱼、人脸这类细节，从哪个 N 开始能被正确还原。

- 到 N3060 / N4084 能还原 → 问题主要是**资源不足**；
- 到 N4084 仍然丢失 → 问题在**方法本身**（生成器能力、缺少语义锚点）。

旧链路（N3060 / N4084）的协议和现在不完全一致，图上要注明，只用于定性判断。

## 二、资源与信道设置

- **图像**：ImageNet development，256×256。
- **资源点**：N = 1024（主）、2048（次），可选 4096。
  - 换算：CBR = N / (3 × 256 × 256)。N1024 → 1/192，N2048 → 1/96，N4096 → 1/48。
- **SNR**：1、7、13 dB，AWGN。
- **能量**：每帧总能量 2N，沿用项目约定。外部方案若使用不同的功率归一化，按其论文定义换算后注明。
- **无法精确匹配 N 时**：取最接近的资源点，在表格和图中标注实际 N，**不插值、不外推**。
- **训练 SNR**：优先使用对应 SNR 训练的模型；借用相邻 SNR 模型时必须注明。

## 四、指标

**常规指标**：PSNR、LPIPS-Alex、DISTS、DreamSim、CLIP ViT-L/14、DINOv2 ViT-L/14、MS-SSIM、ResNet-50 top-1。

**语义错误指标**（新增，必报）
- **语义错误率** = 1 − 和原图预测类别的一致率（ResNet-50）；
- **"自信地错"比例**：重建图 top-1 概率 ≥ 0.5，但预测类别和原图不同的比例；
- **人工检查（可选）**：对 16 张固定样例，两人分别独立判断"主体物体是否与原图相同"，报告一致率。

**统计**：100 张 development 图 × 3 个噪声种子，源配对 bootstrap 95% 区间。外部方案按相同口径计算。

**计时**：各方案接收端单图耗时（同一 GPU、同一口径），用于复杂度对比表。
