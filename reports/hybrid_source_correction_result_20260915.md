# 固定预算数字VAR＋源残差JSCC：完成报告

日期：2026-09-15，Asia/Shanghai。注册队列于20:30:13完成训练、校准、development、计时与统计；随后完成1500次PHY回放和6000张图像的独立指标复算。没有新holdout，没有改动预注册方案或历史结果。

## 结论先行

**本轮预设的联合目标没有达到，且没有合格的校准checkpoint。** 主1/4/7 dB，可靠度融合对完整raw数字自适应的PSNR差仅+0.06735dB，95% CI跨0；LPIPS反而增加0.05254，远超允许的0.005退化。对实际整帧算术码＋FEC也没有达到目标。

但不能说“残差支路完全没用”：相对只输出缩短数字基础的消融，它提高PSNR 2.198dB、降低LPIPS 0.02100。问题在于，这不足以补偿资源改投后失去的保护/真实尺度价值。**可靠度gain相对同参数SNR gain也没有实用增量。**

这是本固定m7/1882/1110分配与小型RGB残差接收器的有界结果，不证明混合JSCC或VAR通信无效。停止自动追加本点训练/搜索，保留全部checkpoint和失败记录；不把这批不合格诊断点升级为新的强基线。

三个训练臂只有同一小通信骨干上的融合区别：add直接相加；snr_gain仅使用名义SNR；reliability_gain额外读取实际CRC与实际接收波形到ML路径的距离。两个gain控制参数完全相同。

接收器始终保留body CRC失败的实际完整ML候选；header失败固定灰图。TX不读取RX噪声、CRC或实际重建，RX不读取源图/真误码位置。训练中的实际失败未过滤。均未换FEC、视觉骨干、输入尺度或搜索功率/分配。

## 2. 选模不是“成功选出了好模型”

预注册目标：主1/4/7 dB，相对两条完整数字自适应分别满足LPIPS平均退化≤0.005，再在可行点中选最高PSNR；期望开发集PSNR增量≥0.5dB且CI下界>0，LPIPS差CI上界≤0.005。

三个分支在5000、10000的完整1000源校准中均无可行点。按原规则选出的10000点仅是**最小最大违约的诊断点**，不是合格强基线。没有为得到赢家而重选checkpoint或放宽容差。

可靠度分支完整1000源校准：PSNR19.41176dB、LPIPS0.233758。raw参考LPIPS0.179883，算术参考0.179750；相对较严约束`0.179750+0.005`仍超出0.049008。以下表格是对这些冻结诊断点的development结果，不混用校准值，也不混入上一轮1000 holdout的19.41dB/0.1792。

## 5. 连续纠偏有重建收益，但没有兑现强系统优势

缩短数字基础消融主区为17.49583dB/LPIPS0.257299。加入本残差链后的配对变化为：

- ΔPSNR **+2.19817dB**，CI[+2.04325,+2.35362]。
- ΔLPIPS **−0.021000**，CI[−0.022846,−0.019195]。
- 高13/19相对同一缩短基础：PSNR+3.53258dB，LPIPS−0.040451。

缩短基础只作为消融，忽略已经支付的连续支路，不能用它替代完整强对照。这个比较确认的是**新增残差链输出有重建收益**，没有额外做打乱连续观测/同划分非残差编码对照，不能进一步宣称已孤立证明全部增益来自独立实例信息或残差编码最优。

固定m9在低SNR太激进，所以不能只挑它当弱对照。原自适应的较好整体结果来自按SNR选这些固定候选，而不是更多总资源。

对主LPIPS做同一批源/噪声的均值记账：

`混合－自适应 = (缩短基础－完整m7) + (混合－缩短基础) + (完整m7－自适应)`

`+0.052536 = +0.022540 −0.021000 +0.050996`。

即残差链几乎补回缩短保护带来的LPIPS损失，但没有再提供完整数字自适应增加真实尺度的那部分感知收益。这是所测输出的均值差分，不是把三个物理因果效应宣称为彼此独立。

## 6. 失败分层说明什么

下表按每SNR300次传输计数，三个混合分支使用完全相同的数字观测，因此数字事件相同。

| SNR | Header失败 | Body CRC失败 | 正确校验接受 | 观察到的错误接受 |
|---:|---:|---:|---:|---:|
| 1 | 0 | 300 | 0 | 0 |
| 4 | 0 | 1 | 299 | 0 |
| 7 | 0 | 0 | 300 | 0 |
| 13 | 0 | 0 | 300 | 0 |
| 19 | 0 | 0 | 300 | 0 |

1dB时，完整raw m7原本有246/300次正确校验接受；缩成1882数字uses后变为0/300。**这说明这个分配点确实严重削弱了低SNR基础保护。** CRC失败不意味着所有token都错；本实验保留了全部实际候选，不是丢弃造成的灰图损失。

另一方面，7/13/19dB数字基础已经全部正确，混合LPIPS仍明显落后，所以不能把全部差距归因于数字误码。当前残差表示、有限连续资源、训练与受限融合的组合，也未取代更多真实尺度的价值。

CRC在1dB全部失败、≥7dB全部通过，在本开发网格上几乎由SNR决定。这限制了它相对已知SNR的额外信息量；不能因此否定其他信道区间/更丰富可靠度信息。没有观察到漏检也不等于漏检概率为零。

## 8. 计算成本：TX的轻量优势消失

主1/4/7、同32个旧源、CPU输入→CPU输出、batch1，单位ms：

| 系统 | TX | RX | 处理时间和 |
|---|---:|---:|---:|
| 原raw数字自适应 | 10.073 | 62.358 | 72.432 |
| 实际算术数字自适应 | 60.280 | 75.049 | 135.329 |
| 本混合可靠度gain | 69.336 | 62.681 | 132.017 |
| 感知DeepJSCC | 2.258 | 3.023 | 5.282 |

混合TX实际运行VQ、VAR补全和连续Encoder，**没有用训练缓存免掉在线计算**。它的处理时间约为raw的1.82倍，主要增加在TX。与算术链同量级，但没有质量优势。不同系统计时来自不同session/驻留组合，不能把小差异解释为纯机制加速。

三臂联合训练＋校准约1.300 GPU驻留小时；共享21k基础缓存另约0.399小时。正式开发评测约55.37秒、新系统计时约198.90秒；工程profile与最终独立复算另计。三臂共用数字回放/基础渲染，不把总时长简单除以3声称单臂独立成本。

这些是处理/计算成本，**不是含空口、排队、模型加载、类别获得和CSI估计的端到端时延**；GPU驻留小时也不等于显卡能耗。

## 10. 研究定位与下一步边界

数字基础＋连续残差已有直接先例，原文核对见`hybrid_related_work_20260915.md`。本轮没有复现并战胜HDA等原系统，也没有验证新的可靠度融合增量。next-scale在这里来自冻结VAR基图；这个三通道gain并不是新的逐尺度读取机制。

接收器还很受限：连续Decoder只读其观测和SNR，数字基图主要在末端相加，可靠度仅改变三个通道增益。因此结果不应外推为所有条件融合/混合JSCC无效。但也不能把一个未达约束的固定原型包装成已成立的新方法。

**建议保留数字自适应为现有感知工作点、感知Deep为像素工作点；本固定混合点冻结为对照与负结果，不自动加训、换大网络、改分配或再开搜索。** 若继续，先根据“低SNR保护损失”和“正确基础时仍有感知差距”选择唯一要解释的因素，再另行登记，不用增加模块掩盖现有问题。

TX已知真实类别、TX/RX理想共享名义SNR的假设继续披露。DINO本轮未用于训练/选模，但参与过历史数字模式开发，不能称为全流程独立指标。旧1000 holdout已经帮助形成此假设，本轮不把它当新独立测试。此次有界任务完成，VAR通信的总体研究目标尚未完成。
