## 为什么还需要最小修复

旧 common500 完整尺度 4/10 dB 的源流来自较早实现环境，与当前冻结 H800 源流不一致。终点编号相同、码长碰巧相同，都不等于同一实际码流，不能直接把旧质量分数配到新版源码利用率。原文件和分数全部保留。

逐源、逐原噪声核对 9,000 个逻辑方法帧后，6,579 帧可复用：部分尺度 4/10 的 3,000 帧、两个家族 T1-C 修正版 19 dB 的 3,000 帧，以及可由另一家族完全相同既有事件承接的 579 帧（4 dB 9、10 dB 570）。剩余 2,421 帧均属完整尺度 4/10 dB（分别 1,491、930），每个都是独立物理事件，最多 4,842 次头部/正文译码。

本核验仅进行了 CPU 元数据、文件 SHA、原像素与分数绑定检查，没有新增信道、模型、重建、评分或 bootstrap 调用。修复入口另行冻结，由 root 审核登记后唯一执行。独立 RX 只取实际收到的码流；相同实际 RX 输入可直接复用已保存像素，评分按源和像素哈希去重。实际新增重建及评分数须以修复的真实 ledger 为准。

## 版本与证据

- source_records_3000.csv：源码长度、容量、实际终点及来源身份。
- event_reuse_audit_9000.csv：每逻辑帧的旧/新载荷、profile、图像、分数复用结论。
- repair_budget.json：固定 2,421 物理事件差异清单的 descriptor 与预算。
- input_manifest.json：逐个输入文件的 path、bytes、SHA-256。
- completion.json：CPU 核验结果，不是修复科学完成。
- figures/source_utilization_ecdf.*：实际 500 源经验分布，不从均值伪造 CDF。

第一次 CPU 审计在读第一条 T1-C 事件时因元数据嵌套字段不同而停止，未进行任何科学调用。v2 仅修正该字段读取，实际退出 0，耗时 121.410554436 秒；原失败记录保留。

后续统计直接复用已保存的 10,000 × 500 bootstrap 索引（原 seed 2026100701），每源先平均三次噪声，再直接配对计算区间；不重新抽样，不相减边际区间。修复完成前，本报告不声称完整尺度 4/10 dB 的同版本质量已经交付。
