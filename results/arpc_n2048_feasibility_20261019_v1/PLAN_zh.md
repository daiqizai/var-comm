# ARPC 完整终点曲线与 N2048 双方法可行方案

本轮交付为现有数据整理和传输布局设计。新信道帧、模型推理、训练、重评分、bootstrap 均为 **0**；不含 N2048 的科学执行授权或启动器。原 N1024 比较保持原样。开始时远端 main 为 `fbc17ae300e46bfdab56c22f989752545a5c9b3c`，tracked tree 干净，没有需要覆盖的新结果。

## 2. 推荐的最小验证问题

比较“同样 2048 个复信道符号和同样保护条件下，两种方法各自的完整表示”，不把它称为每种方法分别优化 MCS 后的最好系统性能。

- NeST-Com：现有熵编码 **m10、K=0、680 token** 的完整流与原 D_c。不是 raw，也不回退成部分尺度。
- ARPC：现有 native256 **e7** 的完整对象，包含实际 caption 与所有已终止原生流，不替换为 e6。
- 校准装入率：两者均用原 ARPC cal100 的同 100 个 canonical source_id；原始源文件 SHA 一致。
- 后续正式验证建议沿用原 `external_common100_v1` 的同 100 源、4/10/19 dB、各源三次噪声 6201/6202/6203；这是已使用过的 common500 子集，不称新盲测。与 cal100 分开，不用测试质量选档位。
- 首选两方法、两子帧均用 **64-QAM、5/6**。它是现有 12 个合法档位中唯一让两方法 cal100 完整对象都 100% 装入的共同档位。后续不再扫描 MCS，也不追加五方法。

NeST-Com 单独使用 64-QAM、2/3 已能全部装入，因此固定共同 5/6 不是 NeST-Com 的可靠性最优配置。这里主动固定共同 MCS 是为了回答完整表示的受控比较问题；若以后要比较各自优化后的最优系统，必须另行定义实验，不能混用两种结论。

两方法继续使用各自原 tokenizer、先验与重建模型；同源、同信道预算不代表训练数据、模型规模或推理成本相同。完整表示实验也不能单独用于归因原 N1024 部分尺度方法的所有优势。

## 3. 两个既有 N1024 子帧：逐项付费

每张图固定占两个连续子帧，每个 `68 header + 956 body = 1024`，总计 **136 header + 1912 body = 2048 复符号**。相同标准星座平均 Es=2，标称总能量 4096；实际有限帧能量逐帧记录，不强行归一到 4096，不加功率分配、重传或反馈。

每个 body 使用已有独立 LDPC `(k,n,q)=(4780,5736,6)`，原 20 次迭代等设置保持；不能将 `ep_phy.Backend.plan` 的 956 改成 1912，也不能将两个块误报成一个更长 LDPC 块。已有 catalogue 保存了 12 档实际构造的 layout_id；新重组协议仍需独立资格核查，现有合法 LDPC 不等于新协议已验证。

每个子帧的信息位布局：

`length13 | reassembly96 | fragment_bytes | known_zero_padding | CRC16`

length13 计本片的 `reassembly96 + fragment_bytes`，外层 CRC16 覆盖前面的长度、重组记录、片内容及已知补零，沿用原 CRC 定义。两次长度共 **26 bit**、两次外层 CRC 共 **32 bit**；两次 68 符号付费 header 不可省略。header 原 12 bit profile、16 bit header CRC、6 bit termination 及原实际编码/重复映射都保留在 68 符号内。

建议的保守重组记录每片 96 bit（每片都付费）：

| 字段 | bit |
|---|---:|
| version | 4 |
| codec | 2 |
| endpoint | 4 |
| fragment_index | 1 |
| fragment_count_minus_one | 1 |
| pair_id | 32 |
| original_bit_length | 14 |
| reserved_zero | 6 |
| whole_object_CRC32 | 32 |
| 合计 / 两片 | 96 / 192 |

所有整数 MSB-first；版本 1，codec 0=NeST / 1=ARPC，endpoint 10/7，片序号 0/1、片数减一为 1，reserved=0。pair_id 是本次事务序号，不是免费源图索引；避免跨对象拼接。CRC32 使用 CRC-32/ISO-HDLC，覆盖 `b'N2048PAIR1' + codec:uint8 + endpoint:uint8 + original_bit_length:uint16be + packed_object_bytes`，两片重复该 CRC32 并已经计费。它只作错误检出，不宣称绝对排除误收。

先取得**完整、已终止的源码对象**，再作传输层字节分片。NeST 的比特流按 MSB-first 打包，最后不足一字节补 0，原始 bit 数由 14 bit 字段传输；ARPC 对象原本已字节对齐。总 B 字节分成 `ceil(B/2)` 和 `floor(B/2)`，不会靠文件名或发送端未传信息恢复长度。额外算术 finish 为 0，因为这不是两条独立源码算术流；原完整流中的全部 finish 始终保留。**任何半片都不能单独送入源码解码器。**

每片最多 `floor((4780−13−16−96)/8)=581` 字节，合计 **1162 字节 = 9296 bit** 完整对象容量。

两片新增/外层信息开销共 **250 bit = 26 + 32 + 192**，另有 NeST 整对象 0–7 bit 字节对齐与实际 LDPC 信息补零。不要把总 9560 信息位直接当源码容量：按平衡字节分片，最大装入时还剩 14 bit 信息补零。重组记录是本方案保守设计，不声称最小开销；未为了装入省去第二长度、CRC、header 或源码 finish。

新协议采用独立 public catalogue 和新 wrapper：主方案 4 个数据 profile（两 codec × 两片）及 2 个 null profile（两 codec），全部由实际收到的 12 bit profile 指定；本片 codec/endpoint/片序号字段需与收到的 profile 一致。旧类、旧 catalogue、旧结果字节不变。装不下仍发送两个完整 null 子帧并保留失败分母，不以换成短终点伪装成功。

接收必须同时满足两个实际 header 合法、两个 CRC16/length/padding 合法、paid 重组字段一致、片序号齐全、整对象 CRC32 合法、原源码 canonical parser 合法，才使用独立共享模型恢复完整表示。任一失败整图固定灰；不 KEEP，不拿半片作前缀，不注入 TX CDF、原图、token、caption、未传长度或 TX hash。实际收到但错误且通过全部接收检查的对象也必须保留其真实输出，事后审计才与 TX 比较，不用真值纠错或改灰。

两方法共享同一 2048 维复标准噪声实现；前/后 1024 取不同片段，不把同一 1024 噪声复制两遍。source_id/seed 只用于试验噪声配对；源码接收与补全不读取这些真值。两个子帧使用独立公开 counter 的 scrambling，不增加隐含信令。

## 4. 校准装入率与可靠性边界

| 每片调制 / 码率 | 两片净源码容量 bit | NeST m10 / 100 | ARPC e7 / 100 |
|---|---:|---:|---:|
| 16-QAM 2/3 | 4848 | 2 | 0 |
| 16-QAM 3/4 | 5472 | 12 | 0 |
| 16-QAM 5/6 | 6112 | 53 | 0 |
| 64-QAM 1/2 | 5472 | 12 | 0 |
| 64-QAM 2/3 | 7392 | 100 | 0 |
| 64-QAM 3/4 | 8352 | 100 | 0 |
| **64-QAM 5/6** | **9296** | **100** | **100** |

其余 QPSK 档和 16-QAM 1/2 两种完整表示装入率均 0；完整 12 档见 CSV。cal100 的 NeST m10 实际 4836–6784 bit，均值 6009.32；ARPC e7 为 8576–8992 bit，均值 8806.64。先用 cal100 得出共同档位后，既有验证集长度清单复核两者也各 100/100 装入，未使用测试质量。这个比例与 SNR 无关。

但旧独立单帧可靠性样本中，同一 q6、5/6 在 4/10/19 dB 分别为 **0/100、0/100、100/100** 成功。它们来自历史不同载荷和 catalogue，仅提示风险，既不能给新双帧贴成功标签，也不能直接平方得到新成功率。**4/10 dB 很可能是两种完整表示都无法可靠送达的压力点；19 dB 是更有辨识度的完整表示质量点。** 两个低 SNR 点仍应报告，不能为图好看而删除。

因此目前能确认“2×1024 容量可行”，不能确认“4–19 dB 完整表示无线可用”。若目标是在低 SNR 也可靠恢复完整表示，现有 N2048、现有档位和无反馈条件可能不够；本轮不擅自增加带宽、改源码或训练。

## 5. 净新增计算量与复用边界

本轮已读取并校验 cal100 / external_common100 两方法 **400 份完整源码对象**，同源档案 SHA 一致；新 tokenizer / TX 概率遍历均可为 **0**。正式验证所需的 200 份完整对象全部已有。新 header/profile、重组记录和片载荷改变了 PHY 输入，**旧 N1024 无线发送不能复用为新两片发送**。

建议的下一次最小完整验证只固定一个共同 MCS，不做信道校准搜索：

| 正式逻辑方法帧：100 源 × 3 SNR × 3 噪声 × 2 方法 | 1800 个 N2048 对象 |
| 每对象两个物理 N1024 子帧 | 3600 子帧 |
| 每子帧 header/body 最多各一次译码 | 7200 次包译码 |

资格的 12 个 clean 对象应独立接收，12 个受控损坏对象验证拒绝/重组行为；不能用“复用旧像素”代替新的协议独立源码往返资格。它们属于工程资格，不加入正式质量统计。

在已核查的最终缓存域中，验证集完整 ARPC e7 图像为 0/100，NeST m10 为 1/100，因此正确接收状态有 **199 个图像缓存缺口**。它是条件性工作量，不能叫已经完成：只有实际重组对象、模型、数值设置和运行身份完全一致才可复用；被拒绝的对象直接灰图，合法误收的不同对象可能增加唯一 RX 状态。未穷举所有更早历史图库，不把“未核查”说成绝对不存在。校准 NeST 的 100 张完整图无需为了本次装入率补做；ARPC cal100 e7 全部已有。

拟正式评分保持原七指标版本，按原图—输出像素对和指标身份复用；正确对象缺口对应最多 199 组新图像对，若全七项都缺最多 1393 个标量。包含任意合法误收的保守评分预算为 1800 个新输出对 + 最多 100 个源相关灰图对，即 ≤13300 个标量；资格不评分。来源级先平均三噪声，然后一次直接配对 bootstrap；新结果不改旧 N1024 分数/区间。当前不重评分、不重算 bootstrap，也不承诺固定 GPU 小时。

## 6. 实施前门槛与停止点

仅当用户随后授权执行，才冻结协议与执行登记，完成独立 RX/负例资格后启动上述唯一有限正式网格。未知模型/CDF/源码身份差异保留现场并停止，不自动改阈值或重跑成功调用。现有12档布局只是核账证据；新 header catalogue、重组、真实功率/噪声账仍未获得科学运行资格。

本次交付到此停止：不启动 N2048，不恢复旧任务/计时/备份，不新建自动调度，不扩大到五方法。
