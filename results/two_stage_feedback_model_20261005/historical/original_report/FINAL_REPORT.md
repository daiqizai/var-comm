# N1024 两阶段反馈：资源计费的表模型扫描

本报告只比较冻结质量表与物理概率表推导的期望 DINOv2 ViT-L/14 余弦相似度。没有新信道译码、图像生成、训练或独立视觉指标评测。

## 1. 导频核查与本轮口径

旧 QCSI 直接使用真实瞬时信道，预算只扣反馈、68 符号头部与正文，没有导频。本轮四种方法都扣除同样的 8/16/32 导频符号，仍假设接收端及反馈 SNR 精确；因此结果仅反映资源代价，不包含有限导频估计误差。0 导频仅作诊断。

- `measured_headers`：68 符号头部复用原物理概率曲线；第二头部为 0 时由公共协议唯一确定动作；16 符号头部缺少对应曲线。
- `ideal_controls`：包括第一轮 68 符号头部在内，所有已计费头部均假设可靠；这是控制开销敏感性比较。
- 反馈只包含登记的 SNR bin，没有免费的 ACK/NACK；第一轮失败后的接收结果仍按连续可信前缀规则计分。
- C8 的树 ID 在第一轮头部付费。第二动作由树 ID 和公共 SNR bin 确定；不能依赖接收端不可见的发送端选择。

## 3. 导频、反馈位数、反馈费用与第二头部费用

`matched_axis_effects.csv` 给出只改变一个登记轴、其他控制相同的逐源配对差值。每个资源点可在构造集重新选策略和 m，因此它衡量受限预算下的策略变化，不是单独的信道估计误差。

导频费用分别对比 0；反馈位数分别对比 1 bit；反馈费用分别对比 8 符号；第二头部费用分别对比 68 符号。实测头部模式中的 16 符号缺失项不填零，也不参与比较。同样反馈符号数下改变信息位数仍沿用可靠反馈假设，不表示已有反馈码实现。

## 4. 配对区间与未知事件

`paired_differences.csv` 保留四方法的六组配对比较。区间以同一 200 张源图重采样，5000 次、种子 2026100504；每张图使用积分后的模型期望分数，没有信道 Monte Carlo 样本。这些是描述性源级区间，不包含 BLER 表有限样本、插值、端点尾部、理想 CSI 或模型选择误差；也不作多重比较显著性或实际链路增益声明。

错误接受等未评分事件继续使用独立的 [-1,1] 质量范围，表中另报保守贡献范围。点估计采用原登记的未知状态质量 0，不能将其解释为实际恢复质量。

## 5. 覆盖、资源与发送端代价

完整网格含 10368 个方法行；按构造集选 m 后含 3456 行。其中 288 行缺少登记资产。所有有值策略的路径上界均不超过 N1024。

原 R 的 66 动作曾按 68 符号头部预算剪枝；本轮候选覆盖需按新预算及精确 PHY/Q 对应关系核验。未测码长不能由相邻码长 BLER 冒充；未缓存质量状态不外推。完整覆盖依据绑定的搜索输出与候选清单。

表模型可以使用已缓存质量值，但这不提供实际收发所需的全部资产。FIXED/QCSI 若选择部分尺度，校准源的熵序位置缓存缺口仍会阻止直接实链复现；本轮没有补齐该缓存。

C8 需要发送端计算源图相关的候选恢复质量；缓存查表耗时不能作为部署时延。具体候选状态与神经推断需求见sender_cost.csv；本轮没有测量在线发送时延。

## 缓存辅助指标

主点策略、公共树字典及每源树 ID 冻结后，复用原质量表的 PSNR、LPIPS、CLIP、DISTS、DreamSim、MS-SSIM、原 DINO 与 ResNet-50 分类口径；这些辅助指标未参与选择。DINOv2-L 仍是已参与选策的指标。具体骨干版本按 parent_metric_provenance.json 中原登记的 model_metadata 原样引用。ConvNeXt 和 F 恢复误差在此缓存缺失，不新增推断或填值。

auxiliary_primary_metrics.csv 的 known-state contribution 只含已有质量表状态；有未评分概率时不能把它当完整指标。仅 U=0 时给 total_mean；分类指标未知状态范围为 [0,1]，余弦为 [-1,1]，其余指标不假设边界。配对区间同样只描述冻结表模型的源级差异，不能作为真实图像改善证据。

原登记的评测模型名称（逐字引用；这不是本轮新加载的模型）：

- clip: OpenAI CLIP ViT-L/14 (224px), image-image cosine
- dists: DISTS official learned alpha/beta; torchvision VGG16 IMAGENET1K_V1
- resnet50: torchvision ResNet50_Weights.IMAGENET1K_V2
- dinov2_vitl14: Meta DINOv2 ViT-L/14 standard LVD-142M backbone, no registers, 1024-d x_norm_clstoken cosine
- dreamsim: DreamSim ensemble v0.2.0-checkpoints: dino_vitb16,clip_vitb16,open_clip_vitb16 + LoRA
- ms_ssim: VainF/pytorch-msssim MS-SSIM, RGB, data_range=1, five scales
- existing_dino: Retain registered dino_cosine=DINOv2 ViT-S/14 unchanged; dinov2_vitl14_cosine is a separate added column
- backbone_relationships: Communication encoder/VAR/Dc are separate from these evaluation backbones. DreamSim includes DINO and CLIP families; evaluation metrics are not mutually independent. D_C classification is label-conditioned and descriptive only.
