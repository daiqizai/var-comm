## 3. Swin 控制开销是否有明显可直接修正的问题？

N1024 适配版使用 C6、768 个正文复符号、256 个头部复符号。73 bit 辅助载荷实际由每图 32-bit float32 归一化功率与 41-bit 内容相关六通道子集编号组成；加 CRC16 与 6 个终止 bit，再卷积编码和重复保护成为 512 个发射 bit。N、C 与工作 SNR 已预共享，不能再次把它们说成可删除的头部开销。

固定六个通道不等于固定通道位置。审计中 20 个缓存条件出现 3 个 mask 与 20 个功率值；20/20 同接收观测原生路径核验通过，44/44 既有诊断文件 SHA 一致。不能免费提供每图 mask/功率，也不能仅缩短保护头部就声称多传了已训练 latent。当前检查点只训练 C6/C13，C13 正文已需 1,664 符号；C7 代码可接受但没有训练支持。

因此本轮保留原合法付费适配，未引入新紧凑头部策略，也没有所谓“修正后新性能”可报告。合法的有损元数据量化或不同保护仍是未评价新协议，审计不证明 256 头部符号全局最优。结论仅针对 **SwinJSCC-80k (adapted)**；step 80000 为用户指定检查点，不是充分收敛或官方最佳。训练与校准仅覆盖 1–13 dB，19 dB 保留范围外标记。[side_information_audit.md](T3_swin_sideinfo/side_information_audit.md)；[training_scope.md](T3_swin_sideinfo/training_scope.md)。

旧外部统一耗时在 [external_timing_single_output.csv](T4_resources_cost/external_timing_reuse_v1/external_timing_single_output.csv)：latent JSCC、Swin 与 **native256 BPG**，N1024、7/13/19 dB、development16。它们不与新 4/10/19 计时混合；native BPG 的链路耗时只对可发送样本定义，不把 SOURCE_UNFIT 写成零耗时，不冒充自适应 BPG 的耗时。历史 BPG 单独 exit receipt 本地缺失，保留已发布 completion/输出哈希与审计证据边界。HiFi 不新增统一计时。

## 5. 论文目前应主张什么？

可以主张：在冻结的固定长度 raw token 接口、有限已测工作点和相同调制编码权限下，允许传输部分尺度能改善源信息与纠错保护的折中；完整尺度候选扩充后，N1024 的原对照仍保留。新 N2048 实验证实了收益边界：4 dB 仍有明确增量，10 dB 部分指标增量很小或不确定，19 dB 完整十尺度可发时三种数字方案精确相同。它不是所有 SNR 均有效，也不是对所有同先验编码接口普遍最优。

同先验 VAR 条件熵码必须作为主要对照报告：N1024 的 19 dB 熵码消除了本批图的完整 m9 容量瓶颈，在前三项质量上超过原部分尺度，同时 TX 成本更大；N2048 的 4/10 dB 与部分尺度之间前三项质量差值区间均跨零，19 dB 两者完全一致。因此论文应同时陈述固定长度接口的有限增量、同先验熵码的质量—发送端计算取舍，以及完整尺度可行后的零增量边界，不承诺普遍领先或精确带宽节省。

所有差值均保持“方法−参考”；LPIPS 负值更好，一致率按百分点显示。统计先在每个源图内平均三次噪声，再使用已完成的源图配对统计，10,000 次 bootstrap、seed 2026100701、逐点 95% CI，无多重比较校正。均值为零不总意味着零宽区间，区间包含零也不证明等价。此报告仅读取这些已封印结果，不重新 bootstrap，不以是否显著触发补测或选图。
