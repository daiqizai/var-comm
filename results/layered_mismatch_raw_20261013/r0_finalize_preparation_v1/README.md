This is a CPU-only postprocessor, not a scientific owner or a scheduler. Its preparation and synthetic tests have completed; the actual full-result audit and nomination have not run. It cannot launch R1 or R2.

Before nomination, it requires both supplementary scientific owners' actual successful waits, full immutable registration bindings and all expected actual records. The body supplement must contain exactly 88,896 complete body trials in 1,389 points; all 672 original selection points and original header results remain unchanged. Every trial's recorded public layout, random namespace/counter, CRC outcome partition, hashes, energy and call counts is checked against its 64-trial point closure. The read-only audit aggregates already recorded counts with the registered Wilson formula; it does not regenerate payloads, noise or waveforms.

The clean supplement must close both actual render and score stages with their complete SQLite ledgers, 5,400 reconstructed images and DINO scores, and 200 source feature preparations. The audit checks each original source pixel/token/archive and checkpoint hash, raster prefix hash, image archive and actual image hash, source feature archive and feature hash, original numerical settings, metric identity and the score CSV's full precision. Prior-scale and decoder call sequences are checked, in addition to model and image call counts. The 3,400 historical exact-clean rows and 200 gray-source scores are reused as historical screening evidence; they are not represented as new H800 computations.

Only after those checks does the entry call the previously frozen `r0_screening.rank_and_nominate` on all 689 profiles, 687 × 3 body points, 44 × 200 clean source states and 200 gray-source scores. The original DROP proxy, ranking, tie order and shortlist limits remain unchanged. The proxy is not a strict lower bound and does not infer KEEP's wrong-token reconstruction quality. No 13 dB table enters nomination.

The producer's DINO floating-point validity tolerance is preserved during receipt auditing. The frozen nomination function retains its original stricter interval of [-1, 1]. An actual out-of-range value causes a diagnostic failure; values are never clipped, silently repaired or recomputed. No output nomination directory is created until all checks and the frozen ranking have passed.
